# buyer-auth — 바이어 계정 (이메일/비밀번호 로그인 · 가입 · 어드민 검수)

`klow.kr/` 바이어 공간([`../buyer-platform/`](../buyer-platform/README.md))의 로그인·가입·계정은 지금 **목업**이다
(`KbSignup`·`KbBuyer` — localStorage `kb.buyer`, 아무 비밀번호·아무 6자리가 통과한다). 이 트랙은 그걸 **실제 서버 계정**으로
바꾸고, KLOW 어드민이 가입한 바이어를 보고 검수 상태(배지)를 정하게 한다.

원래 buyer-platform 의 `§7` 24행("계정 + 샘플박스 주문·결제")에 묶여 있었는데 **2026-10-08 사용자 결정으로 계정만 떼어 먼저** 만든다.
24행은 이제 샘플박스 주문·결제만 남는다(이 트랙이 전제).

## 결정 요약 (2026-10-08 사용자 결정)

1. **이메일 + 비밀번호만.** 소셜 로그인 없음.
2. **세션은 한 달 유지 — 짧게 잡지 않는다.** TTL 30일 + 슬라이딩 연장(남은 기간이 절반 아래로 내려가면 다시 30일). 한 달에 한 번이라도 들어오면 로그아웃되지 않는다.
   로그인 화면의 "Keep me signed in" 을 끄면 브라우저 세션 쿠키(창을 닫으면 끝)다.
3. **가입 마지막 단계에서 실제 이메일 OTP 를 보낸다**(Resend · 기존 `EmailVerification` 재사용). 디자인의 3단계(Account → Business → Verify) 그대로.
4. **이메일 인증까지 끝나면 MOQ 구간가 블러가 풀린다.** 계정은 **검수 대기(`pending`)** 로 시작하고, "Verified buyer" 배지는 **어드민이 승인**해야 붙는다.
5. **어드민**에서 가입 바이어 목록 · 계정별 가입 정보와 서류 확인 · 계정 상태(배지) 수정.
6. **사업자등록증·매장 사진은 R2 에 실제로 올린다.** 공개 URL 은 어디에도 내지 않는다(버킷이 공개 버킷이라) — 어드민은 서버를 거쳐 받는다.
7. **비밀번호 찾기**(이메일 OTP 3스텝)도 이번에.
8. ⚠️ **klow_web 소비자 로그인과 완전히 분리한다** — 테이블·쿠키·라우트·클라 쿼리키 전부 따로. 같은 이메일이 소비자 계정과 바이어 계정을 둘 다 가져도 서로 모르는 별개 계정이다.

## 스코프 밖

- 샘플 주문·결제·주문 내역 — 목업(localStorage `kb.orders`) 그대로. buyer-platform 24행
- 문의(`BuyerInquiry`)를 계정에 연결 · 채팅 · 리뷰 — 24·25행
- **서버측 구간가 은닉** — 지금도 카드 `priceUsdCents`(MOQ 구간가)와 PDP `tiers` 가 공개 응답에 실린다. 블러는 여전히 **화면 가림**이다
  (공개 응답이 ISR 캐시라 자격을 섞을 수 없다). 진짜로 가리려면 공개 응답에서 잘라 내고 로그인 전용 엔드포인트를 따로 둬야 한다 — 별도 결정
- 계정 탈퇴 — 계정 화면 버튼은 Request 드로어(운영팀 문의)로 대신한다
- 로그인 실패 잠금 — 스로틀(10회/분)로 대신
- 이메일 변경 · 2FA · 소셜
