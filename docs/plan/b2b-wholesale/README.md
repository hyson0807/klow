# b2b-wholesale — B2B 도매 (바이어 페이지 + 도매가/MOQ + 주문 접수)

해외 바이어(수입상·현지 유통처)가 링크 하나로 들어와 **도매가와 MOQ 를 보고 장바구니에 담아 주문서를
넣는** 브랜드별 페이지. `klow_brand` 의 `b2bpc` 브랜치가 목업으로 만든 것을 서버와 붙여 실동작시킨다.

B2B 는 메뉴를 두 벌 들지 않고 브랜드관 메뉴를 물려받는다(아래 결정 2).

## 한 문단 요약

설계의 요점은 **브랜드가 이미 꾸며 둔 브랜드관을 그대로 쓴다**는 것이다. B2B 는 새 화면을 꾸미는
기능이 아니라 기존 브랜드관 위에 **"도매가 + MOQ" 한 겹**을 얹는 기능이라, 브랜드가 입력하는 값은
제품당 기본 넷(노출·도매가·통화·MOQ)뿐이고 도매의 본론인 **수량 구간별 가격**은 그 위에 선택으로
얹힌다. 구간을 하나도 안 만들면 단일 도매가 제품이다. 인코텀즈·리드타임처럼 도매 실무에 흔한 나머지
필드는 넣지 않았다 — 넣는 순간 등록이 일이 되고, 그럼 아무도 안 쓴다(브랜드 스토리에서 블록 타입을
하나로 묶은 것과 같은 판단).

## 결정 요약

### 1. 신규 테이블 6벌 + 전용 모듈 (2026-09-28 사용자 결정)

`B2bSetting` · `B2bProductTerm` · `B2bPriceBreak` · `B2bDocument` · `B2bOrder` · `B2bOrderLine`.
`src/modules/b2b/` 신규 모듈이 소유하고 `v1/brand/b2b/*`(BrandGuard) + 공개 `v1/b2b/*` 두 표면을 낸다.

⚠️⚠️ **`PUT /v1/brand/applications` 에 얹지 않는다.** `story` 한 칸의 zod 400 이 색·폰트·링크 저장까지
통째로 죽이는 전례가 그 파일 주석에 박혀 있다. `brand-notices` 가 전용 컨트롤러로 간 선례를 따른다.

### 2. 메뉴를 두 벌 들지 않는다 — 브랜드관 메뉴를 물려받는다

바이어 메뉴의 골조는 **브랜드관 '메뉴탭'이 정본**이고 B2B 는 그 위에 덮는 얇은 층이다. 두 벌을 따로
들면 홈에서 줄 이름을 고쳤을 때 바이어 화면에만 옛 이름이 남고, 그때부터 어느 쪽이 맞는지 아무도
모른다. 그래서 B2B 가 저장하는 것은 **"바이어에게 안 보일 줄의 id 목록" 하나**다. 홈에서 줄을 지우면
그 id 는 아무것도 안 가리키게 되고(해가 없다), 다시 만들면 다른 id 라 기본값(보임)으로 돌아온다.

ℹ️ b2bpc 의 `buyer-menu.ts` `buyerMenuStory()` 는 여기서 **빈 페이지 줄을 이미 제거**하고 PDF 자료를
`kind:'link'` 줄로 합성한다(id 접두사 `b2bdoc:`). 홈 메뉴 쪽에 같은 가드가 없던 것이
`brand-menu-schema` 트랙에서 정규화로 해소된다.

### 3. 주문 접수까지 포함, 어드민 관찰 화면은 제외 (2026-09-28 사용자 결정)

바이어가 주문서를 넣으면 서버에 저장되고 `B2bSetting.orderEmail` 로 알림메일이 간다(Resend).
**결제(PG)는 이번 스코프가 아니다.** 다만 주문은 **금액 스냅샷을 통째로 들고 있다**(줄별 단가·합계·
통화) — 나중에 결제를 붙일 때 그 한 건만 읽으면 청구가 서므로 스키마 변경이 필요 없다.

`klow_admin` 은 이 트랙 전체에서 **무변경**이다.

### 4. 바이어 공개 페이지는 klow_web 에 둔다 (2026-09-28 사용자 결정)

b2bpc 는 `klow_brand/src/app/[slug]/b2b` 에 만들었지만 두 가지가 맞지 않는다.

- 공개 브랜드관의 정본은 **klow_web** 이고, klow_brand 에는 staging 기준 공개 라우트가 **하나도 없다**
- **커스텀 도메인은 klow_web Vercel 프로젝트에만 붙는다**(`klow-web` / `klow-web-staging`) —
  klow_brand 에 두면 브랜드 자기 도메인에서 바이어 페이지가 열리지 않는다

→ klow_web `[brandSlug]/b2b` 로 이관하고 `middleware.ts` 의 `STOREFRONT_SEGMENTS` 에 등록한다.

⚠️⚠️ 그 순간 정적 세그먼트 `b2b` 가 `[brandSlug]/[influencer]`(할인 링크)를 이긴다. `Promotion.slug` 는
`name` 에서 자동 생성되고 **예약어 검사가 없어서**, 이름이 "b2b" 인 할인 링크가 조용히 죽는다.
예약 가드를 함께 넣고 기존 데이터를 먼저 조회한다(`implementation-plan.md` §3 5단계).

### 5. 바이어 인증을 만들지 않는다

로그인·토큰·초대가 없다. slug 를 아는 사람은 누구나 열 수 있고, 식별은 주문서에 바이어가 직접 적는
회사명·담당자·이메일·국가뿐이다. `noindex` 로 "unlisted" 를 흉내낸다. `published:false` 면 "준비 중"만
보이고 **링크는 살아 있다**(404 가 아니다).

⚠️ 그래서 `published` 는 **서버가 검증하는 게이트**여야 한다 — 목업에서는 클라이언트 boolean 이었다.

## 목업의 어디가 가짜인가 (서버 붙이기 전 실태)

b2bpc 는 가짜를 **정직하게 고지**한다("이 브라우저에만 저장돼요 · 서버 연결 준비 중").

| 기능 | 실태 |
|---|---|
| 설정 · 도매가 · MOQ · 구간 · 자료 메타 · 메뉴 hidden · 주문 | **전부 localStorage.** 키는 슬러그 스코프 `klow.b2b.v1.<slug>` / `klow.b2b.orders.v1.<slug>` |
| 서버 쓰기 | **PDF 업로드 하나뿐** (`POST /v1/brand/upload` presign → R2 직접 PUT) |
| 읽기 | 기존 스튜디오 쿼리 2개 재사용(브랜드·제품 목록) — 스냅샷 재료 |
| 주문 알림메일 | `notifyB2bOrder()` 가 `return false` 한 줄. `notifiedAt` 은 항상 null 이고 UI 가 그 사실을 고지 |
| 가격표 임포트(엑셀·CSV·PDF, 512줄) | **실제 동작** — 전부 클라이언트 휴리스틱(`xlsx-js-style` · `pdfjs` 동적 import). ⚠️ **AI 가 아니다** — 아래 "AI 도매표 추출" 참고 |
| 미리보기에서 주문 차단 | 실제 동작(`embedded` prop) |
| 결제 | 스코프 밖. 완료 화면이 "No payment is required at this stage." 라고 말한다 |

**구조적 결함(그래서 이 트랙이 필요하다)**: 대시보드와 바이어 페이지가 **같은 브라우저의 같은 키**를
보므로, 실제 바이어(다른 기기)는 항상 "준비 중"을 보고 브랜드의 「주문 N」은 영원히 0건이다.

### ⚠️ 서버 붙일 때 첫 번째로 확인할 것 — PDF 업로드

`B2bDocsCard` 가 `uploadFile(file)` 을 **`kind` 기본값 `'image'`** 로 부르면서 `contentType` 은
`application/pdf` 를 넣는다. 서버 `validation/upload.ts` 의 image 허용 목록은
`image/webp|jpeg|png|gif` 뿐이라 **그 조합은 400 이다.** `kind` 에 `'doc'` 을 추가하고 호출부도 함께
고쳐야 한다(SVG 는 XSS 때문에 계속 막는다).

### ⚠️⚠️ AI 도매표 추출 — b2bpc 에 **없는 기능이다** (2026-09-28 사용자 요구로 추가)

브랜드가 **거래처에 보내던 원본 가격표 엑셀을 그대로 올리면 제품별 MOQ·도매가가 추출**돼야 한다.
b2bpc 의 `b2b-price-import.ts`(512줄)는 그 자리를 **클라이언트 휴리스틱**으로 채운다 — 가로형/짝형/
세로형 3포맷 + 머리칸을 못 찾으면 `guessPairs()` 가 "수량↑ 단가↓" 로 추측한다. **AI 를 쓰지 않는다.**

실파일 한 장으로 그 가정이 깨진다. 사용자가 준
`(PRICE LIST) W.SKIN LABORATORY_EXW_Ver 2027 ★.xlsx` 실측(2026-09-28):

| 사실 | 휴리스틱이 걸리는 지점 |
|---|---|
| 시트 2장, 이름이 **`PRIEC LIST`**(오타) · `IMAGE` | 시트명 기반 판정이 전부 실패 |
| **헤더가 10행** (1~9행은 타이틀 블록) | 머리칸 탐색이 타이틀을 헤더로 오인할 수 있다 |
| 열 = `CODE │ DESCRIPTION │ EAN 13 │ **U/B** │ Units │ **PRICE (USD)** │ TOTAL` | — |
| **수량 구간이 없다** — 단가 하나뿐 | 3포맷 전부 수량축을 전제한다 → 폴백 `guessPairs()` 로 떨어진다 |
| **`U/B` = 박스당 수량**(44·45·72·180·600), MOQ 가 아니다 | ⚠️⚠️ **MOQ 로 오인하면 최소주문량이 통째로 틀린다** |
| 제품 라인 **구분행이 행 사이에 끼어 있다**(`STOP AGING PEPTIDE LINE`) | 숫자 없는 행이 제품으로 읽힌다 |
| 셀에 **줄바꿈**이 들어 있다(헤더·제품명) | 헤더 매칭 정규식이 어긋난다 |
| `IMAGE` 시트는 **블록 반복 구조** + 병합 셀 + 한글/영문 제품명 2열 | 격자 전제가 깨진다 |

→ **AI 로 간다.** 그리고 KLOW 에 **이미 검증된 엔진이 있다** —
`klow_server/src/modules/shipping/rate-sheet-ai.service.ts`(어드민 배송비용·비교요율 국가 상세).
그 2단계 규칙을 그대로 가져온다.

> **AI 는 레이아웃만 판단하고, 금액은 서버가 원본 셀에서 직접 읽는다.**
> 그 파일 주석: *"AI 에게 금액을 받아쓰게 하지 않는다 — 숫자를 LLM 이 옮겨 적으면 자릿수 환각이
> 난다."* 덕분에 저장되는 금액이 **파일값과 항상 일치**한다. 격자로 안 잡히는 변칙 파일만
> `mode:'pairs'` 폴백으로 AI 가 직접 쌍을 돌려준다.

⚠️ **두 경로를 병존시킨다** — 배송비용 탭의 선례와 같다(목록 페이지는 `고객_가격표` 고정 포맷 파서,
국가 상세는 AI). **KLOW 다운로드 양식은 기존 휴리스틱 파서**가, **브랜드 원본 파일은 AI** 가 받는다.
휴리스틱을 지우지 않는다(양식 경로가 싸고 정확하다).

⚠️⚠️ **제품 자동 매칭은 불가능하다.** `Product` 에 **SKU·코드·바코드 필드가 없다**(실측 — `hsCode` 는
통관 코드다). `externalProductCode` 는 마이그레이션 `20260922024806_drop_product_external_product_code`
로 **드롭됐다**(⚠️ 그 마이그레이션은 아직 운영에 안 갔다 — 운영 DB 에는 컬럼이 남아 있지만 코드가
안 쓴다). 그래서 파일의 `CODE`(`wskin008`)·`EAN 13` 으로 맞출 수 없고, **제품명 유사도 + 사람이
미리보기에서 고르는 것**이 유일한 길이다. b2bpc `B2bImportModal` 이 이미 못 맞춘 줄을 `<select>` 로
고르게 하므로 **그 UI 는 살린다.**

⚠️ 엔진은 **`b2b` 모듈에 자체 서비스로 둔다**(`shipping/rate-sheet-ai.service.ts` 를 일반화하지
않는다). 축이 다르고(제품·MOQ·단가·구간 vs 무게·원화) 상한 상수가 그 도메인에 박혀 있어, 일반화하면
잘 도는 요율표 코드에 위험이 간다. **공유하는 것은 패턴과 프롬프트 설계 규칙**이다.
⚠️ `src/common/` 에는 올릴 수 없다 — 도메인 로직이고 `common/` 은 `modules/` 를 import 하지 않는다.

### ⚠️ 데드 코드 — 서버가 지원할 필요가 없는 것

`wholesaleUsd` · `wholesaleDiscountPct` · `lowestTierPrice` · `tierSavingPct` 는 **호출처가 0건**이다.
"D2C 대비 할인율 %" 는 타입·헬퍼만 있고 UI 에 붙어 있지 않다(카드·상세는 취소선 D2C 가만 표시).
환율 훅도 B2B 어디서도 쓰지 않는다. **없는 기능을 위해 서버를 만들지 말 것.**
