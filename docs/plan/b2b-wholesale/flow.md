## §1 전체 흐름

```
[브랜드]  스튜디오 헤더 B2B pill → /b2b
            ├ 도매가 탭  제품별 노출·도매가·통화·MOQ (+ 수량 구간 ≤5)
            │             └ 「가격표로 한 번에 채우기」 — 두 경로
            │                 ├ KLOW 양식 → 클라이언트 휴리스틱 파서
            │                 └ 브랜드 원본 → POST /v1/brand/b2b/import/preview
            │                     (AI=레이아웃만 · 금액은 서버가 원본 셀에서 읽는다)
            │                     → 미리보기에서 제품 매칭 확정 → PUT .../terms
            ├ 자료 탭    언어별 PDF 업로드 + 바이어 ☰ 메뉴에 올릴지·이름
            └ 설정 탭    공개 토글 + 주문 알림 받을 이메일
                             │
                             ▼  PUT /v1/brand/b2b/*   (BrandGuard)
                        ┌──────────────────────────────┐
                        │ B2bSetting · B2bProductTerm  │
                        │ B2bPriceBreak · B2bDocument  │
                        └──────────────────────────────┘
                             │  GET /v1/b2b/:slug  (공개 · 로그인 없음)
                             ▼
[바이어]  klow.kr/{slug}/b2b  또는  {브랜드도메인}/{slug}/b2b
            ├ 홈        브랜드관과 같은 히어로·로고·태그 + 도매 제품 그리드
            ├ ☰ 메뉴    브랜드관 메뉴 물려받음 + PDF 자료 줄
            ├ 제품 상세  도매가 사다리(수량↑ 단가↓) + MOQ + 수량 직접 입력
            └ 장바구니 → 주문서(회사·담당자·이메일·국가·메모)
                             │  POST /v1/b2b/:slug/orders
                             ▼
                        B2bOrder + B2bOrderLine (금액 스냅샷)
                             │
                             ├─→ Resend → B2bSetting.orderEmail  → notifiedAt 기록
                             └─→ 브랜드 대시보드 「주문 N」 → 접수 / 확인 / 완료
```

**결제는 이 흐름에 없다.** 주문서 접수까지가 스코프고, 그 뒤는 브랜드와 바이어가 직접 협의한다.

## §2 왜 브랜드관을 그대로 쓰는가

도매 페이지를 따로 꾸미게 하면 **브랜드가 같은 일을 두 번 해야 한다.** 로고·색·폰트·태그·스토리를
B2B 에서 또 채우게 되고, 한쪽만 고치면 두 화면이 갈린다. B2B 가 브랜드관 위의 **한 겹**인 이유가
이것이고, 그래서 브랜드가 B2B 에서 입력하는 것은 **가격·MOQ·자료·공개여부**뿐이다.

목업은 이것을 `B2bSnapshotBrand` / `B2bSnapshotProduct` 로 풀었다 — 바이어 페이지가 로그인이 없어
`/v1/brand/*` 를 부를 수 없으니, 대시보드가 저장할 때 **바이어 화면이 그리는 데 필요한 값만** 함께
떠 둔 것이다. 서버가 생기면 **공개 엔드포인트 응답이 그 모양을 그대로 돌려주면 된다** — 즉 스냅샷은
클라이언트 저장의 우회책이었고, 서버에서는 **투영(projection)** 이 그 자리를 대신한다. 별도 사본
테이블을 만들지 않는다.

⚠️ 그 투영에서 **태그는 파싱해서 내려보낸다.** `Brand.tagline` 에 태그가
`__klow_brand_tags_v1__:a,b,c` 로 직렬화돼 있어서 원문을 그대로 실으면 **바이어 화면에 내부 키가
찍힌다.** b2bpc 의 스냅샷 타입이 `tagline` 을 아예 담지 않고 파싱된 배열만 담는 이유가 이것이다.

⚠️ **제품 상세 필드를 목록 응답에 다 싣지 않는다.** 목업 스냅샷은 전 제품의 `detailImages` 와 고시
전문(성분·사용법·주의사항·품질보증…)을 통째로 담아서, SKU 가 많은 브랜드는 localStorage 5MB 한도에
걸릴 수 있다고 그 코드가 스스로 경고한다. 서버 응답도 같은 크기가 된다 — **목록은 카드에 필요한
값만, 상세는 제품 단건으로** 가른다.

## §3 왜 수량 구간이 자식 테이블인가

`B2bProductTerm.tiers` 를 Json 배열로 두는 것이 더 작다(최대 5개짜리 짧은 배열이고 항상 제품과 함께
읽힌다). 그럼에도 `B2bPriceBreak` 테이블로 간 이유는 둘이다.

1. **구간 기준 조회가 열린다** — "MOQ 100개 이상 조건인 제품", "이 수량에 단가가 얼마인 브랜드"는
   도매 중개에서 실제로 물어볼 질문이다. Json 이면 전부 앱 레이어로 올라온다.
2. **`@@unique([termId, minQty])` 가 중복 수량을 DB 에서 막는다.** 목업의 `normalizeTiers` 는
   "중복 수량은 뒤 값 우선"으로 조용히 흡수하는데, 그건 편집 중 관용이지 저장 규칙이 아니다.

⚠️ 반대로 **PC 설정 3개는 테이블로 빼지 않았다**(`brand-menu-schema` 트랙). 그쪽은 중첩이 없는 독립
스칼라라 컬럼이 맞다. **"정규화"를 모든 것에 기계적으로 적용하지 말 것** — 판정 기준은 *중첩·순서·
조회·번역이 필요한가* 다.

## §3-A 왜 도매표 추출에 AI 를 쓰는가

브랜드는 **이미 거래처에 보내던 가격표 파일**을 갖고 있다. 그걸 제품 카드마다 다시 치게 하면 제품이
열 개만 넘어도 아무도 안 한다 — b2bpc 주석이 그렇게 적었고 그 판단은 맞다. 문제는 **그 파일의 모양이
브랜드마다 다르다**는 것이다.

b2bpc 는 이것을 **클라이언트 휴리스틱**으로 풀었다(가로형/짝형/세로형 + 머리칸을 못 찾으면
"수량↑ 단가↓" 로 추측). 실파일 한 장으로 그 가정이 깨진다 — `README.md` 의 표 참고
(시트명 오타 · 헤더 10행 · 수량 구간 없음 · `U/B` 가 MOQ 가 아님 · 라인 구분행 · 멀티라인 셀).

⚠️ **휴리스틱의 실패 방식이 나쁘다.** 못 읽으면 에러가 아니라 **그럴듯하게 틀린 값**이 나온다
(`guessPairs()` 가 아무 숫자 쌍이나 수량·단가로 짝지운다). 도매가와 MOQ 는 **돈이고 계약 조건**이라,
"조용히 그럴듯하게 틀린다"는 것이 이 자리에서 가장 위험한 실패다.

### 그런데 AI 에게 숫자를 받아쓰게 하지 않는다

KLOW 에 **같은 문제를 이미 푼 엔진**이 있다 — `shipping/rate-sheet-ai.service.ts`(어드민 배송비용 ·
비교요율의 국가 상세). 캐리어마다 헤더 이름·단위·열 위치가 달라 고정 파서를 못 쓰는, 형태가 똑같은
문제다. 그 해법이 이 트랙의 해법이다.

> **(1) AI 는 "어느 시트 / 어느 열이 무엇 / 단위·통화" 라는 레이아웃만 판단하고,
> (2) 실제 숫자는 서버가 원본 셀에서 직접 읽는다.**

그 파일 주석이 이유를 한 줄로 적었다 — *"AI 에게 금액을 받아쓰게 하지 않는다. 숫자를 LLM 이 옮겨
적으면 자릿수 환각이 난다."* 이 분리 덕분에 **저장되는 금액이 파일값과 항상 일치**한다. 레이아웃은
틀려도 미리보기에서 사람이 열을 다시 고르면 되고(**AI 재호출 없이 재추출**), 금액은 애초에 AI 를
거치지 않으니 틀릴 경로가 없다.

⚠️ 격자로 안 잡히는 변칙 파일만 `mode:'pairs'` 폴백으로 AI 가 직접 쌍을 돌려준다 — 그 경로는
**예외**이고 기본이 아니다.

### 두 경로를 병존시킨다

배송비용 탭의 선례가 그대로 적용된다 — **목록 페이지는 `고객_가격표` 고정 포맷 전용 파서**, **국가
상세는 임의 포맷 AI**. 여기서는 **KLOW 다운로드 양식 = 기존 휴리스틱**, **브랜드 원본 파일 = AI** 다.
양식 경로가 싸고 정확하므로 휴리스틱을 지우지 않는다.

### 제품 매칭은 사람이 확정한다

⚠️⚠️ **자동 매칭이 구조적으로 불가능하다.** `Product` 에 **SKU·코드·바코드 필드가 없다**(`hsCode` 는
통관 코드다). 있던 `externalProductCode` 는 마이그레이션
`20260922024806_drop_product_external_product_code` 로 **드롭됐다.** 그래서 파일의 `CODE`(`wskin008`)
나 `EAN 13` 으로 맞출 길이 없고, **제품명 유사도로 후보만 대고 못 맞춘 줄은 사람이 고른다.**
b2bpc `B2bImportModal` 이 이미 그 UI 를 갖고 있으니 AI 경로에도 그대로 쓴다.

⚠️ 매칭 실패분을 **버리지 않는다.** 조용히 사라지면 브랜드는 "왜 이 제품만 도매가가 없지"를 설명
들을 방법이 없다 — 요율표 엔진의 `SkippedRow` 가 사유를 함께 노출하는 이유와 같다.

ℹ️ 매칭을 자동화하고 싶으면 `Product` 에 브랜드 SKU 필드를 **되살리는** 결정이 필요하다. 이번
스코프 밖이고, 하려면 별도 결정으로 세운다(드롭 마이그레이션이 아직 운영에 안 갔다는 점은 참고).

## §4 왜 금액을 스냅샷으로 박는가

주문은 **그 시점의 계약**이다. 브랜드가 다음 주에 도매가를 올렸다고 지난주 주문의 금액이 따라 움직이면
안 된다. 그래서 `B2bOrderLine` 이 `name` · `image` · `unitPrice` · `lineTotal` 을 자기 안에 든다.

그 덕에 **제품을 지워도 주문 이력이 남는다** — `productId` 를 nullable + `onDelete: SetNull` 로 두면
FK 가 끊겨도 줄이 무엇이었는지 읽을 수 있다. 반대로 `Cascade` 로 두면 제품 하나를 정리했을 때 과거
주문이 통째로 사라진다.

같은 이유로 `notifyEmail` 도 **주문에 박는다.** 설정을 뒤에 바꿔도 "그때 어디로 보냈는지"가 남아야
한다(`notifiedAt` 과 짝이다. `null` = 아직 못 보냄).

⚠️ **금액은 `Decimal` 이다. `Float` 를 쓰지 않는다.** KRW·JPY 는 소수 0자리, USD·EUR·CNY 는 2자리라
표시 자릿수는 갈리지만 저장은 `Decimal(14,2)` 하나가 덮는다.

## §5 왜 바이어 인증이 없는가

B2B 바이어는 **한 번 보고 연락하는 사람**이다. 계정을 만들게 하면 그 마찰에서 대부분이 이탈하고,
브랜드가 바이어를 초대·승인하는 운영 부담이 생긴다(브랜드 가입에서 invitation·TOTP 를 빼고 마찰을
최소화한 것과 같은 판단).

대신 셋으로 감싼다.

- `published` 토글 — **서버가 검증한다.** 끄면 "준비 중"만 보이고 링크는 살아 있다
- `noindex` — 검색에 안 잡히는 "unlisted" 링크
- **rate limit** — 주문 POST 는 메일 발송을 동반하므로 `THROTTLE_TIGHT` 급

⚠️ 조회 쪽은 과하게 조이지 않는다. 박람회 부스·통신사 NAT 뒤에서 한 IP 가 장소 전체를 대표하므로
조이면 정상 방문자끼리 429 로 막고 그게 **조용한 과소집계**가 된다(`public-seeding` 선례).

## §6 이 트랙이 만나지 않는 것

- **`Order` · `Shipment` · EFS · 정산** — B2B 주문은 KLOW 결제·출고를 타지 않는다. 주문서 접수까지다
- **`BrandSubscription` 게이트** — 이번 스코프에서 B2B 공개를 구독 상태로 게이트하지 않는다
  (`published` 토글 하나가 게이트다). 붙일 이유가 생기면 그때 결정한다
- **방문 통계(`BrandDailyStat`)** — 바이어 페이지는 브랜드관 방문에 집계하지 않는다.
  ⚠️ 집계하면 D2C 퍼널(`uniqueCartAdds ≤ uniqueVisits`)에 도매 트래픽이 섞여 브랜드가 설명을 들을
  방법이 없어진다. 현장(`onsite`)을 같은 이유로 제외한 선례가 있다
- **`klow_admin`** — 무변경(README 결정 3)
