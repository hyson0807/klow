# customer-reviews — 배송완료 → 고객 리뷰 요청 메일 + 작성 페이지

손님(구매자)이 제품 리뷰를 **직접** 쓸 수 있게 한다. 배송이 끝나면 그 주문의 고객에게 리뷰
요청 메일을 보내고, 메일 링크로 로그인 없이 들어와 그 브랜드 제품 중 원하는 만큼 골라
평점·글·사진을 남긴다.

지금 klow_web 제품 상세에 뜨는 리뷰는 **전부 대행 수기 입력**이다 — 어드민이 `/admin/reviews`
에서, 브랜드가 스튜디오 제품 편집 패널 `리뷰` 탭에서 넣는다
([`decisions/products.md 2026-08-18`](../../decisions/products.md#2026-08-18)). 그래서 `Review`
에는 `orderId`·`status`·출처 컬럼이 없고 **"구매 확인"이라는 개념 자체가 없다.** 손님이 쓸
경로는 0개다(`public-reviews.controller.ts` 는 GET 전용).

## 결정 (2026-10-01 사용자)

| 결정 | 값 |
|---|---|
| 발송 단위 | **주문 × 브랜드(송장) 1통.** 멀티 브랜드 주문은 브랜드마다 1통 — 배송완료 시점이 달라 시차 발송 |
| 중복 방지 | `ReviewRequest` 행의 `@@unique([orderId, brandId])` — **행이 곧 영수증**이고 구조적 보장이다 |
| 대상 | 배송이 끝난 **모든 주문** — 일반 · 시딩(무가·유료) · 현장(onsite) |
| 노출·권한 | **즉시 노출**(검수 없음) + `Review.source='customer'` 는 **브랜드가 수정·삭제 불가**, 어드민만 삭제 |
| 제품 범위 | 그 **브랜드의 판매중 전 제품 자유 선택.** 실제 받은 제품은 맨 위 `받으신 제품` 섹션에 먼저 |
| v1 포함 | 리뷰 **사진 업로드** · **현장(onsite) 주문** · **메일 8개국어** |
| v1 제외 | 미작성 리마인더 — 주문×브랜드당 정확히 1통 |

**왜 "브랜드 전 제품 자유 선택"인가.** 시딩은 한 사람이 여러 제품을 받고, **브랜드에 등록되지
않은 제품을 받았을 수도 있다**(발급 품명이 자유 텍스트다). 받은 것을 맞히려 들면 틀리고,
일반 주문과 규칙이 갈리면 화면·서버 분기가 하나 늘어난다. 한 규칙으로 둔다.

## 범위 밖 (이 트랙이 건드리지 않는 것)

- `SeedingClaim.reviewCompleted` / `SeedingLink.reviewCompleted` / `ManualSeedingRecord.reviewCompleted`
  — **브랜드가 켜는 "인플루언서가 SNS 후기를 만들었다"** 플래그다. 이름만 비슷하고 KLOW 사이트
  리뷰와 **다른 축**이며 서로 읽지 않는다.
- klow_web `/my` 의 `myReviews` 죽은 메뉴(`href` 없음) — 회원 전용 "내 리뷰" 목록. 이 트랙의
  작성 경로는 비로그인 토큰이라 회원 축이 없다. 다음 트랙 후보.
- 리마인더 발송 · `helpful` 버튼 · 리뷰 신고 · 정렬·필터 · 페이지네이션(서버 200건 상한 유지).
- 어드민 검수 큐 — 즉시 노출로 정했으므로 `Review.status` 를 만들지 않는다.
