# seeding — 크리에이터 시딩(샘플) 프로그램

- **모듈 경로**: `src/modules/seeding/`
- **주 클라이언트**: `klow_brand`(시딩 링크 발급·요율/비교 미리보기·이용계약서 서명, + 제품 가격 탭의 배송비 청구 계산기가 `GET /v1/brand/seeding/quote` 재사용) + `klow_web`(바이어 공개 페이지 `/seed/:token` claim/checkout) + `klow_admin`(배송비용·해외배송 비교요율 표 편집).
- **데이터 모델**: `SeedingClaim`(**신청 1건 = 1명 = 1주문 = 1송장** — `linkId`+`orderId @unique`, `state`(reserved/confirmed/released/cancelled)·`reservedUntil`·신청자별 `countryCode`/`selectedSkus`/`recipientInstagram`/`snsMemo`/`reviewCompleted`. 단일·다인원 링크가 **같은 모델**을 쓰며 브랜드 목록의 행 단위다), `SeedingLink`(발급 링크 — token·국가·무게·결제주체/선택모드 2×2 매트릭스·통관 스냅샷 + 고객 결제용 금액 `shippingFeeKrw`/`productPriceKrw`(물품가, 선택) + 발급 배치 라벨 `campaignName`(≤40자) + 브랜드 담당자 메모 `memo`(≤80자) + 수화인 입력 `recipientInstagram`·브랜드 메모 `recipientSnsMemo`(발송대기 "받을 사람 SNS 주소", ≤200자, 2026-07-02 `add_seeding_link_recipient_sns_memo`)·`reviewCompleted`(후기 제작 완료 토글, 2026-06-29 `seeding_instagram_review`)), `ManualSeedingRecord`(KLOW 이전 자체 시딩 수동 import 기록 — `data` JSON + `reviewCompleted`, brand scope), `SeedingServiceAgreement`(후청구 이용계약서, `brandUserId` 당 1행), `SeedingRate`(국가×무게 배송비 요율표, 모든 비용/마진 포함 — 시딩·일반주문 공용), `ShippingRate`(carrier=EMS|DHL **비교가** 티어 — rateKrw 가 곧 표시가), `Order`/`OrderItem`(시딩 주문, `isSeeding=true`).
- **시딩이란**: 브랜드가 크리에이터에게 보낼 무료/유료 샘플 발송 링크(`/seed/:token`)를 발급하면, 크리에이터(바이어)가 이메일·배송지를 입력해 **무료 claim** 하거나 **유료 checkout**(배송비 결제)으로 신청한다. **한 링크가 몇 명을 받는지는 `mode` 가 정한다** — `single` 은 1명(기존), `multi` 는 정원(`maxClaims`)까지 선착순으로 여러 명이 신청하고 신청자 수만큼 EFS 송장이 나간다. 신청 1건 = 1주문 = 1송장은 두 모드 모두 동일하다.
- **2×2 매트릭스**: 링크는 `paymentBy`(brand=후청구 무료 / customer=바이어가 배송비 + 선택 물품가 결제) × `selectionMode`(brand=브랜드 지정 / customer=후보 중 바이어 선택)로 분기한다. 선택 후보(`selectionSkus`)는 등록 product ID 가 아니라 **자유 텍스트 제품명 라벨**이라 소유 검증 없이 trim·중복제거만 하고, 바이어 선택은 claim/checkout 의 `validateSelection`(후보 멤버십·개수·`selectionLimit` 검증)으로 검증한다.
- **다인원 링크 (선착순, 2026-08)**: `SeedingLink.mode`(single|multi) + `maxClaims`(정원 2~500) + `closedAt`(브랜드 수동 마감/재개방). 발급 위저드의 **첫 질문**이 방식 선택이고, multi 를 고르면 "링크 몇 개" 대신 "최대 몇 명"을 묻고 **링크는 1개만** 만든다. `paymentBy`·`selectionMode` 두 축과 모두 조합 가능.
  - **정원 판정은 `SeedingClaim` 라이브 COUNT 하나뿐**이다(카운터 컬럼 없음). `reserveSlot()` 이 트랜잭션 첫 문장으로 `SELECT … FOR UPDATE` 로 링크 행을 잠그고(`brand-auth.lockBrandUser` 와 같은 이유 — read-committed 재확인만으로는 동시 요청 둘이 같은 스냅샷을 통과한다) 활성 신청 수를 센다. 점유 조건 = `confirmed` ∨ (`reserved` ∧ `reservedUntil > now`). 만료 예약은 **시계가 지나는 순간** 정원에서 빠지므로 보정 쓰기가 없고 드리프트가 불가능하다.
  - **락 구간은 3왕복까지만.** 동시 신청이 이 구간에서 직렬화되므로 문장 하나가 곧 N명의 대기시간이다. 잠금+읽기를 한 문장으로 합치고 만료 예약 청소(`sweepExpiredReservations`, 위생 목적)는 락 밖으로 뺐다. Prisma 기본 트랜잭션 타임아웃 5초로는 십수 명만 몰려도 500 이 나므로 `SEEDING_TX_OPTS`(timeout 20s / maxWait 15s)를 명시한다.
  - **중복 신청 차단 (2026-08)**: 정원을 **행 수로만** 세므로 그것만으론 한 사람이 폼을 반복 제출해 정원을 독식한다(무가 claim 은 결제 단계조차 없어 클릭 두 번이면 된다. 남은 방어인 IP 20회/분 쓰로틀은 NAT 뒤 여러 신청자를 위해 **일부러 완화한** 값이라 중복 방어로 못 쓴다). 그래서 같은 링크 안에서 **이메일·연락처·주소 중 하나라도** 겹치면 `422` 로 거절한다. 판정은 `reserveSlot()` 안, 즉 **링크 행 잠금 안**에서 한다 — 밖에서 하면 같은 이메일 두 건이 동시에 통과한다.
    - ⚠️ **정원 카운트가 `count()` 가 아니라 행 읽기인 이유가 이것**이다. 한 문장이 행 수와 중복 판정을 **동시에** 처리해 락 구간 왕복 수(위 3왕복 규칙)를 늘리지 않는다. 활성 신청은 링크당 최대 `maxClaims`(≤500)라 전 행을 읽어도 부하가 없다 — 두 문장으로 쪼개지 말 것.
    - ⚠️ 그 한 문장은 **`Order` 를 직접 읽고 claim 을 relation 필터로 쓴다**(`order.findMany({ where: { seedingClaim: { linkId, …activeClaimWhere } } })`). 직관적인 `seedingClaim.findMany({ select: { order: … } })` 로 쓰면 안 된다 — Prisma 는 `relationJoins` 프리뷰 없이 중첩 relation select 를 **부모/자식 2쿼리로 쪼개서** 락 구간이 2→3왕복이 된다(실측 확인). ⚠️ **행이 0건이면 자식 쿼리를 생략해 1쿼리로 보이므로 빈 링크로 측정하면 속는다.** 1신청=1주문(`orderId @unique`)이라 행 수는 어느 방향으로 읽든 같다.
    - 비교 대상은 **정원을 점유 중인 신청**(`activeClaimWhere`)뿐이다. 취소·결제실패·만료로 자리가 반납되면 재신청도 함께 열려야 한다 — 아니면 "자리는 남았는데 아무도 못 쓰는" 링크가 생긴다.
    - 판정 규칙은 `orders/recipient-match.ts` 단일 출처다. 브랜드 "발송 대기" 탭의 중복 수령 **경고**(`attachSeedingDuplicates` → `{n}번 주문` pill)와 **같은 원시 정규화**(공백압축·소문자 / 우편 공백제거 / 연락처 끝 10자리)를 공유한다 — 규칙을 각자 두면 브랜드가 보는 "같은 사람"과 서버가 막는 "같은 사람"이 갈라진다. ⚠️ 다만 **비교 필드는 의도적으로 다르다**: 경고는 이름·주소(line1+line2)·우편·연락처를 각각 따로 보고(겹친 필드를 UI 에 강조), 게이트는 이메일·연락처·주소(**국가+우편+line1+line2+city 전부 일치**하는 합성 키)만 본다. 한쪽 모양을 다른 쪽에 맞추지 말 것.
    - 빈 값끼리는 절대 일치로 보지 않는다 — 이 가드가 없으면 연락처를 안 적은 신청자끼리 서로를 차단한다.
    - ⚠️ **409 가 아니라 422 다.** klow_web `/seed` 는 409 를 "선착순 레이스"로 해석해 링크를 재조회하고 **정원 마감 화면**으로 넘긴다(`handleClaimError`) — 409 로 던지면 중복 신청자에게 "정원이 찼습니다"가 잘못 안내된다. 서버엔 `code` 규약이 이미 있지만(brand-auth 의 `user_not_found` 등, klow_brand 는 `ApiError` 로 읽는다) **klow_web 의 `fetchJson` 이 body 를 `API {status}: {message}` 문자열로 뭉개서** code 를 못 읽는다 — 그래서 지금 판별자는 상태코드이고, payload 에는 `code: 'seeding_duplicate_claim'` 을 klow_brand 와 같은 모양으로 미리 실어 둔다(klow_web 이 `ApiError` 를 도입하면 그때 code 로 좁힌다). 바이어에겐 **어느 정보가 겹쳤는지 밝히지 않고**(링크를 아는 제3자가 특정인의 신청 여부를 떠볼 수 있다) `seed.duplicate` 전체 화면으로 안내한다.
    - 고객 결제 경로에서 **본인 예약 재사용 분기가 먼저**라(쿠키/`userId` 증명) 결제창을 다시 여는 본인은 이 게이트를 타지 않는다. 쿠키 없이 다른 기기로 재진입하면 이제 막히는데, 종전엔 자리를 하나 더 먹었으므로 개선이다. ⚠️ dedupe 키 일치를 "본인 증명"으로 쳐서 예약을 **재사용**하게 만들지 말 것 — 남의 이메일을 아는 사람이 10분 창 안에 그 주문의 배송지를 덮어쓸 수 있다.
    - 스키마 변경·마이그레이션·백필이 **없다**(판정을 `Order` 컬럼에서 즉석 계산). 그래서 **기존 신청에도 자동 소급**된다.
  - **고객 결제 예약(10분)**: checkout 진입이 `state=reserved` 로 자리를 선점한다. 정원이 작을 때 이탈 한 번이 링크를 얼려버리지 않도록 세 겹으로 막는다 — (1) **본인 예약 재사용**: 로그인 사용자는 `userId` 로, 게스트는 **`klow_order` 쿠키에서 복원한 주문 id**(`guestOrderIdFromToken`)로 자기 예약을 찾아 새 자리를 잡지 않고 그 주문을 갱신한다(안 그러면 한 사람이 두 번 시도해 정원 2를 혼자 소진한다). 쿠키가 이미 서명된 orderId 를 담고 있어 **클라이언트가 따로 보관·전송하지 않는다**, (2) **결제 실패·취소 시 즉시 반납**(`payment.reportFailure` → `released`), (3) TTL 10분. 만료 후 결제가 도착하면 **확정하고 경고 로그**를 남긴다 — 거절하면 결제한 고객이 아무것도 못 받기 때문이고, 그 대가로 드물게 정원을 1 초과할 수 있다(화면은 `3/2명` 처럼 정직하게 표시).
  - **취소는 자리를 돌려준다**: 송장 취소(`performEfsCancel`)는 그 **신청만** `cancelled` 로 바꾸고, 정원에서 빠져 한 자리가 다시 열린다(안 돌려주면 정원 10명 링크에서 9명만 받게 된다). single 링크는 기존 동작대로 링크까지 `cancelled`, multi 는 링크를 계속 열어둔다.
  - **`SeedingLink` 미러는 single 전용**이다(`mirrorLinkAfterClaim`) — multi 는 주문이 여러 개라 `orderId @unique` 에 담을 수 없고, 그래서 `status` 도 pending 에 머문다. "아직 받는가"의 답은 언제나 claim 라이브 카운트(`accepting`)이지 `status` 가 아니다. ⚠️ 어드민 통계의 "열린 링크 수"(`stats.service`)는 이 이유로 다인원 링크를 과대 계상하는 근사값이다.
  - **송장 화면은 `order.seedingClaim` 을 읽는다** — 다인원 주문은 구 1:1 관계(`order.seedingLink`)가 null 이라, 그것만 읽으면 라벨·상세 모달에서 선택 제품·인스타·캠페인명이 조용히 빈 값이 된다. klow_brand 는 `seedingOf(order)`(shipping.model.ts) 한 곳에서 claim 우선·링크 폴백으로 푼다.
  - **정원 판정은 `summarizeCapacity()` 하나**가 한다 — 바이어 페이지(`getByToken`)와 브랜드 목록(`toLinkDTO`)이 같은 함수를 호출하므로 "받는 중인가"가 두 화면에서 갈라질 수 없다. 브랜드 DTO 는 그 결과를 **`accepting`**(아직 신청받는가)·**`deletable`**(삭제 가능한가, `deleteLink` 규칙과 동일)로 내려주고 클라는 mode·정원·마감을 재조합하지 않는다.
  - **바이어 화면은 사유를 구분**한다 — `unavailableReason`: `claimed`(1인용 링크가 이미 사용됨) / `full`(다인원 정원 소진) / `reserved`(다른 사람이 결제 중, 곧 열릴 수 있음 + `retryAfter`) / `closed`(브랜드 수동 마감) / `cancelled`. ⚠️ `single`·`multi` 를 구분하지 않으면 1인용 링크 재방문자에게 "캠페인 정원이 찼습니다" 같은 다인원 문구가 나간다. 남은 자리는 **≤5 일 때만** 노출한다(100명 링크의 "97자리 남음"은 소음).
  - **쓰로틀**: 다인원은 통신사 NAT·같은 사무실 뒤에서 여러 사람이 신청하므로 claim/checkout 제한을 IP당 **20회/분**으로 완화했다(구 5회는 정상 신청자끼리 서로를 429 로 막는다).

- **표시 제품명도 같은 규칙 — 어드민·브랜드 화면 전체 (2026-08-17):** `OrderItem.productName` 을 그대로 렌더하던 화면들이 동결된 통관 품명(`Korean Skincare Serum`)을 운영자·브랜드에게 보여주고 있었다. **박스 내용물과 화면이 어긋나는 것**이라 전부 `displayLines()` 규칙으로 통일했다. ⚠️ 브랜드 지정 링크는 `SeedingLink.itemNames`(위 항목)가 이름의 출처라, 아래 미러들도 `selectedSkus` 가 아니라 **`customsDeclaredNames` 규칙**(customer→selectedSkus / brand→itemNames)을 따라야 한다. **펼침은 전부 클라가 한다** — 서버는 이름만 내려보낸다. ⚠️ 서버가 `items` 를 펼치면 `items.length` 가 "라인 수"에서 "표시 행 수"로 조용히 바뀌어 그 값을 쓰는 화면이 **"1개 라인" 위에 3줄**을 그린다(실제로 그랬다). 또 `SHIPMENT_INCLUDE` 의 `items` 는 **ShipmentItem 행**이라(`orderItemId` 가 발급·취소의 키다) 애초에 펼치면 안 된다. 그래서 응답별로 이름을 싣는 방식만 다르다 — `listPendingGroups` 는 명시 매핑이라 **`declaredNames: string[]`** 를 따로 내리고, `GET /admin/orders*` 는 `ADMIN_ORDER_INCLUDE`(신규 — **상세 전용**. 목록은 이 값을 안 읽는데 조인만 얹히고 Prisma 가 중첩 relation 을 2쿼리로 쪼갠다)로 `seedingClaim` 을 싣고, `SHIPMENT_INCLUDE` 는 이미 claim 을 갖고 있다. 미러는 `klow_admin/src/lib/seeding-display.ts`(`buyerSelectedNames`/`displayLines`/`shipmentDisplayLines`)와 `klow_brand/.../shipping/shipping.model.ts`(`displayItems`/`displayItemsOf`) 두 개이고 **서버 `seeding-display-name.ts` 가 정본**이다. 커버 범위: 어드민 주문 상세·송장 상세·발급/취소/실패 표·배송추적·정산, 브랜드 발송대기 상세·배송중 상세·목록 카드·정산. ⚠️ **정산 라인도 펼치지만 합계는 불변**이다 — 펼친 행은 수량 1이고 단가가 같아 `Σ(단가 × 1) = 단가 × 원래 수량`(EFS 26번과 같은 산술). 접힌 라벨(`itemsLabel`)과 펼친 목록(`settlementItems`)이 같은 규칙을 써야 "Glow Serum 외 1건"을 펼쳤을 때 다른 이름이 안 나온다.
- **고객 대면 표시도 실제 제품명 — 격리 해제 (2026-08-31):** 위 두 항목이 통관·내부 화면을 실제 제품명으로 고쳤지만 **고객 화면만 예외로 남아 있었다** — 브랜드 지정 시딩을 받은 바이어의 `/track`·주문확인 메일에 동결된 통관 품명(`Korean Skincare Toner`)이 그대로 떴다. 이제 두 경로도 `SeedingLink.itemNames` 를 쓴다. ⚠️ **표시와 통관의 규칙이 완전히 같아졌으므로 파생을 한 벌로 합쳤다** — `SEEDING_DISPLAY_CLAIM_SELECT`+`SEEDING_CUSTOMS_CLAIM_SELECT` → **`SEEDING_ITEM_NAMES_SELECT`**, `buyerSelectedNames`+`customsDeclaredNames` → **`seedingItemNames()`**, 그리고 `DisplayClaim` 의 `link.itemNames?: never` 가드는 **제거**했다(두 벌을 남긴 채 "동기화하세요" 주석을 다는 형태를 피한다). 소비자 네 곳(주문확인 메일·`/track`·EFS 캡슐·어드민 발송대기/주문상세)이 전부 이 함수를 거친다. ⚠️ **`itemNames` 는 2026-08-18 부터 채워진다** — 실측으로 그 이전 발급분(브랜드 지정 링크 313개 / claim 196건)은 전부 빈 배열이고 **복구할 값이 없어** 종전대로 통관 품명 폴백이다(백필 없음, 시간이 지나면 자연 해소). ⚠️ 브랜드가 **물리적으로 담는 것은 자기가 정하고** 우리는 발급 시점에 카탈로그에서 `quantity` 개를 랜덤 추출해 동결할 뿐이라, 이 이름은 "그 브랜드의 실제 제품"이지 "박스 내용물의 보증"은 아니다(그래도 `Korean Skincare Toner` 보다는 참이다). ⚠️⚠️ **같은 작업에서 `displayLines()` 가 중복 이름을 한 줄로 합치게 됐다**(수량 합산, 등장 순서 보존) — 브랜드 지정 링크는 등록 제품보다 박스당 수량이 많으면 같은 제품을 반복 추출하는데, 종전 규칙(펼친 행은 늘 `×1`)이면 24개 링크가 고객 화면에 24줄로 뜬다. **EFS 24번은 `mergeCapsuleItems` 가 이미 캡슐 1개 + 수량 합산으로 접어 보내므로** 합치는 쪽이 송장과 일치한다(실측: PINOGEN 24개 링크 = 6종 × 각 4개). 합은 늘 원래 수량과 같아 개수 라벨·26번 신고총액 전제가 유지된다. ⚠️ 클라 미러 두 개(`klow_admin/src/lib/seeding-display.ts`·`klow_brand/.../shipping.model.ts`)도 **2026-09-02 에 같은 접기로 맞췄다** — 브랜드가 품명을 직접 적기 시작하면서 중복이 정상 케이스가 돼("세럼 2 + 크림 1") 내부 화면만 3줄로 뜨는 게 곧바로 드러났다. ⚠️ 금액은 영향 없다(라인 금액을 쓰는 화면이 전부 `단가 × quantity` 라 접힌 행이 `×1` 두 줄과 합계가 같고, 어드민 정산 합계는 애초에 raw `items` 에서 센다). ⚠️ `itemsLabel` 의 개수는 **서로 다른 이름 수**로 세야 한다. ⚠️ `displayLines()` 에 선택적 `imageFor` 인자가 생겨 `/track` 이 썸네일도 채운다 — 시딩 `OrderItem.productImage` 는 **항상 빈 문자열**이라(실측 446/446) 안 채우면 빈 회색 박스가 남는다. 실측 커버리지 709/743(95%)이고 매칭 실패·`Product.image` 미등록은 종전대로 회색 박스. 인자를 생략하면 동작이 완전히 동일해 메일 경로는 무변경. 마이그레이션·백필 없음.
- **고객 대면 제품명 = 읽기 시점 파생 (2026-08):** 표시 경로도 같은 파일이 소유한다. `selectionMode='customer'` 링크에 한해 **주문 확인 메일 · `/track` 배송추적**에서 `SeedingClaim.selectedSkus` 로 표시 이름을 갈아끼운다. 단일 출처는 `seeding/seeding-display-name.ts` 의 `SEEDING_DISPLAY_CLAIM_SELECT` + `buyerSelectedNames()` + `displayLines()` 이고, 메일 경로(`orders/order-confirmation-email.ts` — `PaymentService`·`SeedingService` 두 발송부 공용)와 추적 경로(`orders.service.getTracking`)가 같은 함수를 거친다. 고른 제품 N개면 **표시 라인 N행으로 펼친다**(시딩 `OrderItem` 은 항상 1행이라 안전 — 통관 캡슐 펼침과 개수가 같아야 고객이 본 것과 송장이 갈리지 않는다). ⚠️ **펼친 행의 `quantity` 는 1로 덮는다** — 고객 선택 링크의 `OrderItem.quantity` 가 이미 선택 개수(위 `seedingLineQuantity`)라 그대로 복사하면 "3줄 × 각 3개 = 9개" 로 제곱이 된다. 각 제품 1개씩이 정확하고 합이 원래 수량과 같다. `selectionMode='brand'` 는 고를 대상이 없으므로 랜덤 영문 통관명 그대로다. ⚠️ **시딩 주문은 메일에서 라인 금액을 숨긴다** — `unitPriceUsd` 가 통관 신고가라 실결제액(무료 claim $0 / 유료 checkout 배송비+물품가)과 무관하기 때문이고, 무료 시딩은 라인·총액 모두 `Free` 로 표기한다. 총액(`totalUsd`)은 그대로 정확하다. 회귀 가드: `seeding/__tests__/seeding-display-name.spec.ts`, `orders/__tests__/order-confirmation-email.spec.ts`.

**엑셀 왕복 (목록 페이지, 2026-08)** — `export` 는 **임포트 파서가 그대로 읽는 포맷**으로 내보낸다. 내려받아 고친 파일을 같은 업로드 입력에 되올리면 반영되고, 운영팀 원본 가격표도 같은 경로를 계속 쓴다(새 업로드 버튼 없음).

- **시트 1 `고객_가격표`** — 행=무게(kg), 열=국가 한글명. col0 헤더는 반드시 `무게(kg)`(파서가 `무게` 로 시작하는 행을 헤더로 찾는다). 티어가 0개인 국가도 **빈 열로 포함**해 엑셀에서 바로 채울 수 있고, 행은 DB 에 존재하는 `weightG` 전체의 합집합이라 국가마다 셀이 비는 게 정상이다(국가 상세 AI 임포트로 무게 축이 갈릴 수 있음). 이 시트를 **맨 앞**에 두는 것도 규칙 — `parseSheet` 는 시트명을 못 찾으면 첫 시트로 폴백한다.
- **시트 2 `청구수수료`** — `ISO / 국가 / 청구수수료(원)`, 정본은 `ShippingCountry.efsBillingFeeKrw`(efs-billing 이 EFS 실비에 더하는 국가별 정액). 매칭 키는 **ISO2 우선**(실재 국가인지 확인 후), 실패 시 국가 한글명. **이 시트가 없으면 임포트가 조용히 건너뛴다** — 운영팀 원본은 이 시트가 없고 종전과 동일하게 동작해야 하기 때문이다.
- **빈 수수료 칸 = 미변경**(0 으로 덮어쓰지 않는다). 목록 표의 인라인 편집이 "빈 값 → 기본 1000" 으로 폴백하는 것과 **의도적으로 다르다** — 98개국 파일에서 빈칸을 값으로 밀면 전 국가가 뒤집힌다. 범위(0~`EFS_BILLING_FEE_KRW_MAX`) 밖이거나 숫자가 아닌 칸은 무시하고 `invalidFees[]` 로 경고에 띄운다.
- **미리보기가 삭제를 먼저 보여준다** — 적용이 국가 단위 전체 교체라 엑셀에서 지운 무게 칸은 사라진다. `removedTierCount`/`removedTiers[]` 로 국가별·티어별로 노출한다. `status` 판정에 **수수료 변화도 포함**해서, 수수료만 고친 국가가 '미변경' 배지로 떠 건너뛰이는 일이 없게 했다.
- ⚠️ **티어가 안 온 국가(수수료만 고친 경우)에는 티어 replace 를 걸지 않는다.** 걸면 그 국가 요율표가 통째로 지워진다. `import/apply` 응답은 `{applied, feeUpdated}` 이고, 값이 그대로인 수수료는 업데이트하지 않아 `feeUpdated` 가 부풀지 않는다.
- ⚠️ `@Get('export')` 는 **`@Get(':iso2')` 앞**에 선언해야 한다 — 뒤면 `iso2='export'` 로 먹힌다.

**AI 요율표 추출 (국가 상세, 2026-08)** — 위의 `import/preview`·`import/apply` 는 `고객_가격표`(국가×무게 매트릭스) **고정 포맷 전용**이라, 캐리어에서 받은 국가 하나짜리 요율표(헤더 이름·단위·열 위치가 매번 다름)에는 못 쓴다. 그래서 국가 상세(`/seeding-cost/[iso2]`)에 별도 경로를 뒀다 — **목록 페이지의 기존 업로드와 무관하게 병존**한다.

- **AI 는 레이아웃만 판단하고 금액은 서버가 원본 셀에서 직접 읽는다.** 71~140행 금액을 LLM 이 옮겨 적으면 자릿수 환각이 나므로, AI 응답은 `{mode, sheetName, orientation, weightIndex, priceIndex, weightUnit, dataStart/EndIndex, currency, weight/priceHeader, notes}`(`RateSheetLayout`) 뿐이다. 저장되는 값은 항상 파일값과 일치한다. 유일한 예외가 `mode:'pairs'` — 격자로 표현이 안 되는 변칙 파일에서만 AI 가 `pairs[{weight,price}]`(≤1000쌍)를 직접 돌려주고, 그 외에는 항상 `'grid'`(스키마 `.catch('grid')`).
- 서비스는 `shipping/rate-sheet-ai.service.ts`(`RateSheetAiService`, ShippingModule 소유) — `inferLayout()`(OpenAI, `OPENAI_MODEL ?? gpt-4o-mini`, `temperature:0` + `json_object`, 시트당 앞 40행×30열·셀당 40자만 프롬프트에 실음) + `extract()`(**LLM 미경유 결정론적 파싱**) + 후보 열 수집. `LogisticsRateService.aiImportPreview()` 가 이를 호출하고 기존 `buildTierDiff` 로 diff 를 만든다. AI 가 없는 시트명을 지어내면 첫 시트로 보정하고, 인덱스를 `-1` 로 두고 헤더 이름만 맞춘 경우(`repairIndexes`)엔 후보 목록에서 이름으로 되찾는다. OpenAI 응답이 비었거나 스키마에 안 맞으면 502.
- 숫자 파싱은 **일부러 엄격하다**(`toNumber`) — 통화기호·콤마·kg/g/원 표기만 떼고 **나머지 전체가 숫자일 때만** 받는다("3지역" 같은 헤더에서 3kg 을 주워오는 사고 방지). `0.5~1` 같은 구간 표기는 **상한**을 쓴다(요율 무게는 "이 무게까지" 상한 티어). 같은 무게가 두 번 나오면 뒤 값이 이긴다.
- **열 오선택 복구**: 응답에 `candidates`(숫자 5개 이상 든 열/행 + 헤더)를 함께 실어, 어드민이 미리보기에서 무게/가격 열을 바꾸면 **같은 파일 + `layout` 을 재전송해 AI 없이 즉시 재추출**한다. 추출 0건이어도 400 을 던지지 않고 candidates 와 함께 돌려주는 이유가 이것 — 던지면 어드민이 바로잡을 화면 자체가 안 뜬다.
- **버리는 행은 노출한다**: `SeedingRateUpsert` 와 같은 상한(무게 1~50,000g / 0~10,000,000원)을 벗어난 행은 `skipped[]` 에 사유와 함께 담겨 경고 배너로 뜬다(예: 50kg 초과 티어). 통화가 KRW 가 아니면 400.
- **적용**은 AI 를 다시 타지 않는다 — 미리보기에서 확인한 티어를 그대로 `PUT :iso2/tiers` 로 되돌려 보낸다(`tiers` 1~300개, `mode` 기본 `replace`). `replace` 는 그 국가 티어 전체 교체(목록 업로드와 같은 의미), `merge` 는 들어온 무게만 지우고 다시 깔아 나머지 기존 티어를 보존한다. 전체 교체가 지울 기존 티어는 미리보기 `removed[]` 로 먼저 보여준다(표준 소형 티어 100g/250g/750g 이 조용히 사라지지 않도록). 없는 국가면 404, 응답은 `{saved, removed}`.

## admin-shipping-rate.controller.ts (`@Controller('admin/shipping-rates')`) — 파일 위치: `src/modules/shipping/`

> 전체 라우트 `AdminGuard`. EMS/DHL **비교가** 티어(`ShippingRate`, carrier=EMS|DHL, rateKrw=표시가) — KLOW 시딩가가 직접발송보다 얼마나 싼지 보여주는 표시 전용. `carrier` 쿼리/파라미터(`EMS`|`DHL`) 필수(아니면 400). 어드민 **해외배송 비교요율** 탭.

| Method | Path                                        | 기능                                               |
|--------|---------------------------------------------|----------------------------------------------------|
| GET    | `/admin/shipping-rates?carrier=`            | 캐리어 국가 목록 + 요율 티어 커버리지(개수·무게·요율 범위) |
| GET    | `/admin/shipping-rates/export?carrier=`     | 그 캐리어의 현재 요율표 xlsx 다운로드              |

**엑셀 왕복 (목록 페이지, 2026-08)** — 배송비용 탭과 같은 왕복을 비교요율에도 붙였다. `export` 는 **임포트 파서가 그대로 읽는 포맷**으로 내보내므로, 내려받아 고친 파일을 같은 업로드 입력에 되올리면 반영된다(캐리어 원본 요율표도 종전 경로를 그대로 쓴다 — 새 업로드 버튼 없음).

- **캐리어당 파일 1개**다(`?carrier=`, 시트 1장). 두 캐리어를 한 파일에 담지 않는 이유는 시트명이 캐리어별이기 때문이다.
- ⚠️ **탭을 잘못 고른 업로드는 리더가 거절한다**(`WrongSheetError` → 400). 왕복을 붙이면서 세 탭(EMS·DHL·배송비용)의 내보내기 파일이 **형태가 완전히 같아졌다** — 헤더도 국가 열도 동일하고 시트명만 다르다. 첫 시트 폴백을 그대로 뒀더니 EMS 파일을 DHL 탭에 올려도 `unmatchedHeaders: []` 로 **미리보기가 완벽해 보이는 채** EMS 요율이 DHL 에 저장됐다(반대 방향은 비교요율이 고객 결제 배송비로 들어간다 — 더 비싸다). 그래서 **아는 시트명일 때만** 거절하고, 시트명이 제각각인 **운영팀 원본은 종전대로 첫 시트 폴백**을 탄다(폴백은 그쪽을 받으려고 있는 것이다). 경계는 `__tests__/shipping-rate-export.spec.ts` 의 '탭을 잘못 고른 업로드' 3케이스가 잠근다.
- 시트명은 `xlsx-grid.ts` 의 `CARRIER_SHEET_NAMES`(EMS `원본요율(할인전)` / DHL `DHL수출요율(개인·물품)`) — **리더와 라이터가 이 상수 하나를 공유하는 게 왕복의 전부다.** col0 헤더 `무게(kg)` 도 파서의 헤더 행 탐색 조건이라 고정이다.
- 매트릭스 라이터는 배송비용 export 와 **공용**(`shipping/rate-matrix-xlsx.ts` `buildRateMatrixSheet`). 행=DB 에 존재하는 `weightG` 전체의 합집합, 열=`ShippingCountry` 전체라 **티어 0개 국가도 빈 열로 나간다**(엑셀에서 바로 채우게). 빈 칸은 파서가 건너뛰므로 그 국가는 미리보기에 아예 안 뜬다 — 되올려도 기존 값이 지워지지 않는다.
- ⚠️ **임포트 리더가 SheetJS 가 아니다.** 배송비용은 `XLSX.read` 로 읽지만 비교요율은 `xlsx-grid.ts` 의 자체 OOXML 리더(`readSheetAOA` → `parseCarrierSheet`)로 읽는다(운영팀 EMS 원본이 한컴셀 산 `x:` 접두사 파일이라 SheetJS 0.18.5 가 조용히 로드 실패). 즉 **SheetJS 가 쓴 파일을 자체 리더가 되읽는** 구조라, 라이터를 건드리면 `__tests__/shipping-rate-export.spec.ts` 의 왕복 스펙이 먼저 깨진다. 그 스펙이 이 기능의 안전장치다.
- **미리보기가 삭제를 먼저 보여준다** — 적용이 국가 단위 전체 교체라 엑셀에서 지운 무게 칸은 사라진다. `removedTierCount`/`removedTiers[]` 로 국가별·티어별 노출(배송비용과 동형). `status` 는 손댈 필요가 없었다 — 기존 `tierStatus` 가 집합 크기 차이로 이미 `changed` 를 낸다.

**AI 요율표 추출 (국가 상세, 2026-08)** — 위 배송비용(`/admin/seeding-rates/:iso2/import/ai-preview`)과 **같은 기능·같은 엔진**(`RateSheetAiService`)을 비교요율에도 붙인 것이다. 동작 규칙(레이아웃만 AI·금액은 서버가 원본 셀에서 직접·엄격한 숫자 파싱·`candidates` 로 열 재선택 시 AI 재호출 없음·`skipped[]` 노출·KRW 아니면 400·적용은 AI 미경유)은 전부 동일하므로 위 절을 참고한다. 다른 점만:

- **캐리어 축이 하나 더 있다.** `(carrier, iso2)` 가 URL 파라미터이고 body 에는 없다(`ShippingRateBulkReplace` = `{tiers, mode}`). `ShippingRateService.aiImportPreview()` / `replaceTiers()` 가 담당하며, ⚠️ **조회·삭제 범위에 `carrier` 가 반드시 들어간다** — 빠지면 같은 국가의 반대 캐리어 요율이 통째로 지워진다(`__tests__/shipping-rate-ai-import.spec.ts` 가 이걸 잠근다).
- 금액 필드명이 다르다 — 추출기는 시딩과 공용이라 `costKrw` 로 돌려주므로 서비스가 `rateKrw` 로 옮긴다. 상·하한은 `ShippingRateUpsert` 와 동일(무게 1~50,000g / 0~10,000,000원).
- 목록 페이지의 `import/preview`·`import/apply`(고정 포맷 다국가 매트릭스)와 **병존**한다 — 그쪽은 `원본요율(할인전)`/`DHL수출요율(개인·물품)` 시트 전용이고, 이쪽은 캐리어가 보내온 국가 하나짜리 임의 포맷용이다.
- 어드민 UI 는 `/shipping-rates/[iso2]?carrier=EMS|DHL` 국가 상세이고, 미리보기 모달은 배송비용과 **같은 컴포넌트**(`klow_admin/src/components/AiRateImportModal.tsx`)를 쓴다 — 모달은 금액 필드를 읽지 않아(무게·개수·중립 `diff` 만) 두 도메인 DTO 를 그대로 받는다.
