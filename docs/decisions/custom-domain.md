## 브랜드 커스텀 도메인 — P1 서버 기반 (2026-08-21)

브랜드가 자기 도메인(`shop.brandA.com`)으로 브랜드관을 여는 기능의 **서버 절반만** 들어왔다. ⚠️ **아직 아무 프론트도 이 API 를 부르지 않는다** — 실제 서빙은 klow_web 미들웨어(P3), 브랜드 등록 UI 는 klow_brand(P4)다. 설계 정본은 [`docs/plan/custom-domain/implementation-plan.md`](../plan/custom-domain/implementation-plan.md), 모듈 문서는 [`docs/server/modules/brand-domains.md`](../server/modules/brand-domains.md). ⚠️ **경계가 핵심이다**: 커스텀 도메인은 **둘러보기·담기까지만** 맡고 **로그인·결제·주문조회는 `klow.kr`**(핸드오프) — 그래서 프록시가 없고 결제창 호출 도메인이 오늘과 같아 PG 전제가 안 바뀐다. 신규 `BrandDomain` 테이블(`host @unique` = 라우팅의 유일한 키, `role primary|redirect`, `status pending|verifying|active|error`) + 라우트 5개(`/v1/brand/domains` CRUD 4 + 공개 `GET /v1/storefront/resolve?host=`). ⚠️⚠️ **Vercel 의 `verified` 는 "접속이 되는가"가 아니라 "소유권이 다투지 않는가"다** — 우리가 소유하지도 않은 도메인이 추가 즉시 `verified:true` 로 온다(실측). `active` 전이는 반드시 **`verified && !misconfigured`** 로 **두 API 를 모두** 본다(`domain-status.ts`). ⚠️⚠️ **apex 판정을 우리가 하지 않는다** — `brandA.co.kr` 은 레이블 3개지만 apex 라(Public Suffix List) 레이블 수를 세면 첫 한국 고객부터 잘못된 DNS 를 안내한다. 정본은 Vercel 응답의 `apexName === name` 이고, `domain-host.ts` 는 **정규화·거부만** 한다. ⚠️ **DNS 값도 하드코딩 금지** — `getDomainConfig` 의 `rank:1` 권장값을 저장해 그대로 띄운다(`rank:2` 는 legacy 라 같이 띄우지 않고, CNAME 후행 점은 제거). ⚠️ 브랜드는 **호스트를 하나만** 입력하고 그게 apex 면 `www` 가 `role='redirect'` 로 자동 동반 등록된다 — **거꾸로(서브도메인 입력 → apex 자동 등록)는 절대 하지 않는다**(브랜드의 기존 홈페이지를 뺏는다). 페어 실패는 primary 를 롤백하지 않고 삭제는 페어 단위다. ⚠️⚠️ **`PUBLIC_BRAND_WHERE` 에 구독 게이트가 없다는 걸 이 작업에서 처음 발견했다**(status `notIn` 뿐 — 구독 게이트는 제품 쪽 `isPurchasable()` 에만 있었다). 그래서 **브랜드 축 규칙의 단일 소유자를 `brands/brand-selects.ts` 로** 세웠다 — select(`BRAND_SERVICEABLE_SELECT`) · JS 술어(`isBrandServiceable`, 별칭 `canServeStorefront`) · Prisma where(`BRAND_SERVICEABLE_WHERE` / `BRAND_NOT_SERVICEABLE_WHERE`) 세 형태를 한 블록에 두고 `product-selects.ts` 도 이걸 호출한다(**네 벌이던 규칙이 한 벌로**). ⚠️ 하나를 고치면 나머지 둘도 고칠 것. ⚠️ Prisma 짝이 없던 동안 `cleanupOrphans` 가 부정형을 손으로 써서 **pending·rejected·withdrawal_pending 브랜드가 정리 대상에서 통째로 빠져** 있었다(서빙은 막혔는데 Vercel 등록만 영원히 남는다) — 테스트 스텁이 정본 상수를 참조 동일성으로 확인해 손으로 쓴 절이 들어오면 즉시 throw 한다. ⚠️⚠️ **`main.ts` 의 Origin 정적 배열이 술어로 바뀌었다** — 분류·정책표는 **`common/origin-policy.ts`** 가 소유하고 스펙이 잠근다(`origin-exempt.ts` 선례 — `bootstrap()` 안 익명 콜백에 두면 테스트가 닿지 않는다). CSRF 가드(`allowsStateChange`)와 `enableCors`(`corsPolicyFor`, 이제 **delegate**)가 **같은 분류 결과를 나눠 쓴다**(갈리면 반드시 사고). 새 오리진 분류는 표에 한 줄만 추가한다. ⚠️⚠️ **브랜드 오리진의 상태변경은 분류가 아니라 경로로 좁힌다**(2026-08-22 보안 점검) — `allowsStateChange(c, path)` 가 `brand` 에만 `BRAND_STATE_CHANGE_PATHS`(트래킹 비콘 3개 + 부수효과 없는 `/v1/orders/quote`) 정확 일치를 요구한다. 분류만 보고 전 경로를 열면, JSON preflight 는 ACAC 부재로 막히지만 **`application/x-www-form-urlencoded` 같은 simple request 는 preflight 를 안 타** 쿠키가 실린 채 도달해(운영 `SameSite=None`) 악성·침해된 브랜드 사이트가 klow.kr 로그인 손님 명의로 **blind 상태변경**을 낼 수 있다. 커스텀 도메인 화면에서 새 POST 를 부르게 되면 그 목록에 등록해야 한다(fail-closed). `isVerifiedOrigin` 은 **동기**(express·cors 가 sync)라 서비스가 `Set<string>` 스냅샷 + TTL 60초 백그라운드 갱신을 들고, 생성·삭제·상태전이는 **그 자리에서 await 갱신**한다. ⚠️ **정확 일치만 한다 — 와일드카드·서브도메인 확장 금지**(넣으면 전 브랜드 도메인이 CSRF 우회로). ⚠️ 이게 없으면 비콘이 아니라 **브랜드관 화면이 통째로 빈다**(`BrandStorefront` 가 `'use client'` 라 브라우저가 `api.klow.kr` 를 직접 친다). **credentials 는 오리진별로 갈린다** — klow.kr 계열만 `true`, 커스텀 도메인은 `false`(세션을 안 쓰는 설계를 서버가 fail-closed 로 강제). `common/origin-exempt.ts` 는 **무변경**이고 그 스펙이 그대로 통과해야 한다. ⚠️ `/v1/storefront/resolve` 에만 **`@SkipThrottle()`** — 부르는 쪽이 손님이 아니라 Vercel 엣지라 IP 가 하나로 뭉치는데 전역이 60/분 per IP 라, 429 가 나면 미들웨어 fail-open 으로 **전 브랜드 도메인이 동시에** KLOW 홈이 된다. ⚠️ **반영 지연 최대 2분**(응답 캐시 60s + 미들웨어 캐시 60s) — 구독 해지·도메인 삭제 후에도 그만큼 계속 서빙된다(설계상 수용). ⚠️ **`VERCEL_PROJECT_ID` 는 환경별로 다른 값**이다(`klow-web` / `klow-web-staging`) — 스테이징이 운영 id 를 들면 테스트 도메인이 운영 사이트에 꽂힌다. 부팅 fail-closed 가드는 **일부러 안 붙였다**(미설정 시 503 명시 거부). Vercel 호출은 `@vercel/sdk` 가 아니라 **native fetch**(`instagram.client.ts` 관례, API 버전 5개는 2026-08-21 실측 확정: add v10 / get·verify·remove v9 / config v6). ⚠️⚠️ **`cleanupOrphans` 의 유예 시계는 `BrandDomain.updatedAt` 이 아니다**(2026-08-22 정정 — 그전엔 그랬고 그래서 **60일 유예가 사실상 0일**이었다). `active` 행은 다시 쓰이지 않아(폴링 cron 이 `pending`/`verifying` 만 집는다) 그 값이 **활성화된 순간에 얼어붙어**, 오래 잘 돌던 도메인이 구독이 `past_due` 로 떨어지는 **첫 사이클에 즉시** Vercel 에서 제거됐다 — 유예가 막으려던 바로 그 상황(재결제 후 DNS 재설정 강요)이다. 정본은 `brands/brand-selects.ts` 의 **`brandUnserviceableSinceWhere()` + JS 짝 `brandUnserviceableSince()`** 이고 시계는 **원인 축의 행**이 쥔다(`status` 로 배타적인 세 분기 — 승인 축이면 `Brand.updatedAt` / 구독 축이면 `BrandSubscription.updatedAt` / 구독 행이 없으면 폴백). 두 시계 모두 무관한 편집으로 **늘어날 수는 있어도 줄지 않아** 안전한 방향으로만 틀린다. 마이그레이션 없음(§9 F33). ⚠️ 유예 절은 `BRAND_NOT_SERVICEABLE_WHERE` 옆에 **`AND:` 로 얹고**(relation 필터를 한 객체에 두 번 못 쓴다) 런타임 날짜가 박힌 절은 팩토리 옆 `unserviceableSinceOf()` 가 되꺼내 스텁이 정본 JS 짝으로 판정한다. 마이그레이션 `20260821052240_add_brand_domains` 는 `CREATE TYPE ×2 + CREATE TABLE` 뿐 → **롤링 배포 안전 · 백필 없음**. ⚠️ 새 cron(`brand-domain-verify`, 5분)이라 `test/app.e2e-spec.ts` 기대 목록이 **9개**로 늘었다. ⚠️ 호스트 표준형은 **`canonicalHost()` 를 쓰기·읽기가 공유**한다 — 조회 쪽에서 손으로 다시 쓰면 IDNA 가 빠져 한글 도메인이 저장(punycode)과 조회(U-label)로 갈린다. 회귀 잠금은 `brand-domains/__tests__/{domain-host,domain-status,verified-origin,domain-pairing,resolve-host}.spec.ts` + `common/__tests__/origin-policy.spec.ts`. **배포는 P0 과 같은 창에서 klow_server 단독**(프론트가 아직 아무것도 부르지 않는다). 전체 배포 절차는 [`docs/plan/custom-domain/deploy-runbook.md`](../plan/custom-domain/deploy-runbook.md).

## 브랜드 커스텀 도메인 — P4 브랜드 등록 UI (2026-08-21)

위 P1~P3 로 기능은 다 동작하는데 **브랜드가 도메인을 등록할 화면이 없어** 운영팀 수동 호출 없이는 시작조차 못 하던 것을 마무리했다. `klow_brand` 단독 · **서버·web·admin 무변경 · 마이그레이션 없음 · 신규 서버 라우트 없음**(`/settings/:path*` 가 이미 미들웨어 matcher 에 있어 그쪽도 무변경). 위치는 **설정 > 도메인 연결**(`settings/_components/DomainSection.tsx`, `PhoneSection` 처럼 `CollapsibleCard` 껍데기 + 안쪽 매니저 — 접히면 언마운트라 **목록 조회가 안 나가고 폴링이 자동으로 멈춘다**). ⚠️⚠️ **폴링 대상은 `GET /v1/brand/domains` 이지 `POST :id/check` 가 아니다** — 후자는 6회/분 상한이고 1건이 Vercel API 를 2~3회 태워, 10초 폴링이면 천장에 닿아 **브랜드의 수동 "지금 확인" 클릭이 429** 가 된다(cron 이 5분마다 갱신하므로 목록만 다시 읽으면 결과가 따라온다). `pending`·`verifying` 행이 없으면 폴링을 끈다. ⚠️⚠️ **`verifying` 은 "SSL 발급 중"이 아니라 소유권 TXT 챌린지 대기**다(계획 문서가 그렇게 잘못 적고 있었다 — "발급 중"으로 안내하면 브랜드가 기다리기만 하고 TXT 를 영영 안 넣는다). ⚠️⚠️ **`lastError` 를 "에러가 있다"의 신호로 쓰지 말 것** — `refreshOne` 이 확인할 때마다 덮어써서 **정상 `pending` 에도** `'DNS 레코드가 아직 확인되지 않았습니다'` 가 들어 있다(톤은 `status` 가 정하고 `lastError` 는 `error` 행의 사유 줄로만 쓴다. 안 지키면 갓 만든 도메인이 전부 고장난 것처럼 보인다). ⚠️ **`recordValue` 는 빈 문자열일 수 있다** — 그때 `76.76.21.21` 류 폴백을 화면에서 채우면 F3 위반(벤더가 타겟을 옮긴 날 신규 연결이 전부 조용히 실패)이라 **"확인 중…"** 을 그리고 폴링이 채우게 둔다. ⚠️ **apex 판정을 클라가 하지 않는다(F2)** — `lib/domain.ts`(서버 `domain-host.ts` 의 **의도된 크로스 레포 미러**, 정규화·거부·상한만)에 apex 함수가 없고, `pair:null` 의 두 의미(서브도메인이라 없음 / 상한 초과로 서버가 생략)는 **서버가 준 `recordType === 'A'`** 로 가른다(판정이 아니라 서버 `apexName` 결과를 읽는 것). 미러 정합은 서버 `domain-host.spec.ts` 케이스 32건(punycode·over-match 금지 `myklow.kr`/`klow.kr.brand.com`/`notvercel.app` 포함)으로 확인. ⚠️ **`useDomainAvailability` 훅을 만들지 않았다** — 서버에 도메인 availability 엔드포인트가 없어(중복은 `POST` 409 로만 안다) `useSlugAvailability` 를 베끼면 비동기 취소 로직이 빈 껍데기로 남는다 → 순수 `checkDomainInput()` + **기존** `useDebounced`. `CheckBadge` 는 재사용하되 **`CheckMessage` 는 안 한다**(슬러그 전용 한국어를 하드코딩하고 `storefrontLabel(slug)` 를 부른다). ⚠️⚠️ **이 API 의 에러 본문은 세 모양**이다 — A `{code,message}` / B Nest 기본(**502 는 message 가 Vercel 영문 디버그 문자열**, 429 는 `ThrottlerException: …`) / C zod `{error,issues}`(message 키 없음). `extractApiError` 만 쓰면 벤더 영문이 브랜드 화면에 뜨고 `describeApiError` 만 쓰면 403 `subscription_required` 의 좋은 문구가 뭉개진다 → **`code` 유무로 가른다**(로컬 헬퍼 `domainErrorMessage`). ⚠️ **구독 게이트는 안내만 하고 입력은 열어 둔다** — 서버 게이트가 `approved && (어드민 생성 브랜드 || 구독 active)` 인데 `BrandDTO` 에 `submittedById` 가 없어 그 예외를 구분할 수 없고, 잠그면 어드민 생성 브랜드는 도메인을 붙일 방법이 아예 없다(어드민 도메인 UI 가 없다). 최종 게이트는 서버 403. ⚠️ **"지금 확인" 버튼 라벨을 바꾸지 말 것** — 서버가 저장하는 `lastError` 문구 여러 곳이 그 문자열을 그대로 인용한다. ⚠️ `lib/storefront.ts` 는 **`storefrontUrl`·`storefrontLabel` 둘만** `customDomain?` 을 받는다(값 규칙 `https://{domain}/` — **슬러그 세그먼트 없음**, 미들웨어 rewrite 와 대칭). ⚠️⚠️ **`lib/onsite.ts` 의 `onsiteStoreUrl()` 에는 영원히 넘기지 말 것** — 미들웨어가 커스텀 도메인에서 `?mode=onsite` 를 **떼어 내고 307** 해서 부스 QR 이 에러 없이 조용히 일반 모드로 떨어진다(§6-2 링크 도메인화가 가장 먼저 밟을 지뢰). 화면은 **핸드오프 경계**(둘러보기·담기만 / 로그인·결제는 klow.kr)와 **반영 지연 최대 2분**을 연결 전에 안내한다. ⚠️ 배포 순서는 **P3(klow_web) 이후 klow_brand 단독** — 먼저 내면 브랜드가 도메인을 연결했는데 사이트가 안 뜬다. 자세히는 [`docs/plan/custom-domain/implementation-plan.md`](../plan/custom-domain/implementation-plan.md) §5 + [`docs/server/modules/brand-domains.md`](../server/modules/brand-domains.md).

## 브랜드 커스텀 도메인 — P3 서빙 개시 (2026-08-21)

위 P1(서버)·P2(수신부)를 이어 **커스텀 도메인이 실제로 동작**하게 됐다. `klow_web` 단독 · **서버 변경·마이그레이션·신규 i18n 키 없음**. 신규 `src/middleware.ts` 가 ① 본 도메인 즉시 bypass ② `GET /v1/storefront/resolve` 로 Host→슬러그 해석 ③ 경로 rewrite/redirect ④ **커스텀 도메인 전 응답에 `X-Robots-Tag: noindex, follow`** 를 한다. ⚠️⚠️ **`credentials:'omit'`(F8)은 위생이 아니라 화면이 뜨는 조건이다** — `origin-policy.ts` 가 브랜드 오리진에 `credentials:false` 를 주므로 `Access-Control-Allow-Credentials` 가 안 붙고, `'include'` 요청은 쿠키만 빠지는 게 아니라 **브라우저가 CORS 실패로 응답 자체를 막아 브랜드관이 통째로 빈 화면**이 된다(서버가 fail-closed 로 의도한 것). ⚠️ 그래서 `isCustomDomain` 은 `'use client'` 인 `lib/host.ts` 가 아니라 **지시자 없는 `lib/host-classify.ts`** 가 소유한다 — `api.ts`·미들웨어(edge)가 같이 써야 하는데 `'use client'` 모듈을 그쪽에서 import 하면 client reference 가 되어 터진다. ⚠️ **브랜드 도메인에서 통과시킬 경로는 명시 허용목록**(`STOREFRONT_SEGMENTS` = product·cart·track·legal·faq·customer-center)이고 **모르는 최상위 경로는 404** 다 — 예약어면 전부 통과시키던 초기 구현은 기본값의 방향이 틀렸다(새 라우트를 추가하면 **아무도 미들웨어를 안 고쳐도 전 브랜드 도메인에서 세션 없이 열린다**). `RESERVED_BRAND_SLUGS` 는 klow_server 미러라 klow_web 이 편집할 수 없는 파일이기도 하다. **새 최상위 라우트를 만들면 허용목록이나 klow.kr 전용 목록에 등록할 것.** ⚠️⚠️ **`/{seg}` 는 어떤 경로로도 pass-through 하면 안 된다(F11)** — pass-through 된 `shop.brandA.com/brandB` 는 `[brandSlug]` 에 그대로 걸려 **브랜드 B 의 브랜드관이 브랜드 A 도메인에 렌더**된다. **2세그먼트도 마찬가지다**(정본 문서가 "pass-through → 404" 라고 잘못 적고 있었다 — `[brandSlug]/[influencer]` 는 `isBrandSlugAllowed` 만 보고 통과시켜 **브랜드 B 의 세일가까지 적용**하고 `source='promotion'` 비콘으로 **브랜드 B 의 할인 링크 통계를 오염**시킨다). fail-open 은 **루트 `/` 에만** 허용된다. ⚠️ rewrite 는 반드시 **`req.nextUrl.clone()`** — `new URL(path, req.url)` 은 **쿼리를 버려** `?purchased=`(결제 후 브랜드 도메인 카트 정리, 언제나 `/` 로 도착한다)가 통째로 죽는다. ⚠️ 리다이렉트는 **307**(308·301 은 브라우저가 영구 캐시하는데 슬러그·도메인은 가변 DB 상태다). ⚠️ **쿠키가 필요한 경로(`/login`·`/signup`·`/my`·`/orders`·`/seed/*`·`/checkout/onsite`)와 `/shop` 은 미들웨어가 307 로 klow.kr 에 넘긴다** — `/seed/*` 는 예약 슬러그라 그냥 두면 렌더되는데 `klow_order` 게스트 쿠키에 의존하고 **자기 도메인에서 결제창을 연다**(핸드오프로 피하려던 바로 그것). **`/track/{id}?t=` 는 의도된 예외**(쿠키가 아니라 URL 서명 토큰). `/shop` 은 쿠키와 무관하지만 **KLOW 마켓플레이스(경쟁 브랜드 목록)** 라 함께 막고, 같은 이유로 하단 탭바를 커스텀 도메인에서 **통째로 숨긴다**(카트 접근은 브랜드관 FAB). ⚠️ **`?mode=onsite` 는 쿼리를 보존하는 순간 실제로 도달하므로 미들웨어가 떼어 낸다.** ⚠️ 송신부는 `location.assign`(**새 탭 금지** — 인앱 브라우저 컨텍스트 유실)이고 **`peekVisitorId()`**(`getVisitorId()` 금지 — 없으면 만들어 원장 없는 토큰이 된다), 진입점은 **카트 결제 버튼과 PDP 바로구매 둘 다**(하나만 고치면 나머지가 세션 없는 `/checkout` 으로 들어간다). ⚠️ **국가 미선택이면 넘기지 않고 국가 모달을 연다** — 수신부가 `setCountry()`(≠`syncCountry`)를 불러 **`onboardedAt` 까지 찍으므로** `?? 'US'` 로 넘기면 klow.kr 에서 모달이 영구 억제된 채 US 가격으로 결제한다. ⚠️⚠️ **`encodeHandoff` 가 자기 정화(self-sanitizing)다 — "encode 가 만든 것은 decode 가 반드시 받는다"가 불변식**이다. `decodeHandoff` 는 fail-closed 라 **선택 필드 하나만 어긋나도 payload 전체를 버리는데** 송신부가 싣는 값 중 셋이 통제 밖이다(`o = location.host` 는 **로컬·스테이징에서 포트가 붙어 실제로 전량 폐기됐다** · `p` 는 localStorage · `l` 은 persist 스키마). 증상이 "프로모션만 빠짐"이 아니라 **손님이 klow.kr `/cart` 로 떨어져 장바구니가 사라진 것처럼 보이는** 것이라 조용하다. 술어를 export 해 송신부가 검사하게 하면 **검사를 잊는 두 번째 호출부**가 생기므로 `handoff.ts` 가 직접 떨어낸다. ⚠️ `location.assign` 은 진짜 문서 언로드라 `storefront-track.ts` 의 **"언로드 유실 걱정 없음(전부 `router.push`)" 전제가 깨진다** — 방문 비콘이 인플라이트면 담기 전송이 **시작조차 안 한** 상태라 `keepalive` 가 못 구하고 `peekVisitorId()` 도 `null` 일 수 있다(→ **결제 단계 퍼널 영구 0**) → `flushPendingVisit(300ms)` 를 기다린 뒤 이동한다. ⚠️ 루트 레이아웃 컴포넌트(`CustomDomainMount`)에서 **`useSearchParams()` 금지**(전 페이지가 CSR 로 deopt) — `window.location.search` 를 마운트 effect 에서 읽는다(`useCheckoutGate` 선례). ⚠️ 미들웨어 본문은 **try/catch → `next()`** 로 감싼다(throw 하면 **klow.kr 포함 전 호스트·전 경로가 500**). resolve 캐시는 양성·음성 **둘 다 60초**(서버가 60초다) · **실패는 캐시하지 않고 stale 만 읽으며**(fail-closed 면 API 가 흔들릴 때 전 브랜드 도메인이 동시에 죽는다) · `Host` 가 공격자 통제 값이라 **상한 256 + 축출 + fetch 전 문법 검사**. ⚠️⚠️ **`RESOLVE_TIMEOUT_MS` 는 3초이고, resolve 의 느린 쪽 왕복보다 짧으면 기능이 통째로 죽는다** — 1초였을 때 스테이징에서 **모든** 요청이 abort 돼 커스텀 도메인이 한 번도 안 떴다(서버·DNS·Vercel 은 전부 정상이었다). 실측 왕복이 **1.2~1.6초**이고 그중 ~0.75초는 Railway+Neon 기본 지연이라 **서버를 최적화해도 1초 밑으로 안 내려간다.** 판별자는 `/{seg}` 가 404 가 아니라 **503** 이라는 것 — "슬러그가 없다"가 아니라 "해석 자체를 못 했다"는 신호다(§9 F30). ⚠️⚠️ **메타데이터 세그먼트 판정은 정확 일치**(+`-{hash}` 접미)다 — `startsWith` 로 보면 `icon` 접두 하나에 `/iconic` 같은 **실재 가능한 슬러그**가 pass-through 되어 F11 이 뚫린다(2026-08-22 수정, §9 F32). ⚠️⚠️ **`host-classify.ts` 의 `HOST_RE` 는 서버 `domain-host.ts` 보다 좁으면 안 된다** — TLD 를 `[a-z]{2,63}` 로만 받으면 **punycode TLD(`xn--…`)를 거부**해, 서버가 받아 `active` 까지 간 한글 도메인을 미들웨어가 영원히 못 연다(resolve 를 아예 안 부른다). 핸드오프 `o` 도 같이 버려진다(2026-08-22 수정, §9 F31). ⚠️ 결제 진입점은 **`useGoCheckout()` 하나**다(카트 버튼·PDP 바로구매 공용) — 사본 2개를 "둘 다 바꿔야 한다"는 주석으로 지키면 세 번째 결제 버튼이 생기는 날 깨진다. ⚠️ 자격증명 정책의 소유자는 **전송 계층**이다(`api.ts` 의 `canAuthenticate()`) — 세션 훅이 주소창을 다시 묻지 않는다. ⚠️⚠️ **미들웨어가 import 하는 모듈에 부수효과를 들이지 말 것** — onsite 상수를 `useOnsiteStore`(`'use client'` + 최상위 `create()`)에서 가져왔더니 **zustand 가 통째로 edge 번들에 들어가** 77.4 → 82.1 kB 가 됐다(값 없는 `lib/onsite-entry.ts` 로 분리해 복귀). 회귀 잠금은 **`npm run check:handoff`**(klow_web 에 테스트 러너가 없어 tsx 로 도는 순수 함수 10케이스 — punycode 왕복이 F31 을 잠근다, 의존성 추가 0). 배포 순서는 **P0+P1(server) → P2(web) → P3(web)** 이고 P3 는 **klow_web 단독**이다. ⚠️ Vercel 에 도메인 추가 시 **"Redirect to primary domain" 이 붙으면 기능이 통째로 죽는다.** 자세히는 [`docs/plan/custom-domain/implementation-plan.md`](../plan/custom-domain/implementation-plan.md) §4.

## 브랜드 커스텀 도메인 — P2 핸드오프 수신부 (2026-08-21)

커스텀 도메인은 **둘러보기·담기까지만** 맡고 **로그인·결제·주문조회는 `klow.kr`** 이 맡는다(핸드오프). 경계를 건너는 순간 **오리진이 바뀌어 `localStorage` 가 따라오지 않으므로**, 커스텀 도메인의 "결제하기"가 `klow.kr/handoff?h=<base64url>` 로 top-level 이동하고 klow_web 이 상태를 복원한 뒤 `/checkout` 으로 보낸다. 이 PR 은 **받는 쪽만** — 아직 아무도 `/handoff` 를 링크하지 않아 **klow.kr 사용자에게 불가시**다(송신부는 P3). ⚠️ **배포 순서는 P2(수신) → P3(송신)** — 뒤집으면 손님이 없는 `/handoff` 에서 404 를 본다. 넘기는 것은 **상태 4개 + 복귀 주소 1개**: 카트 라인 `[productId, quantity]` · 가격 기준국 · `promotionCode` · `visitorId` · 복귀 host. ⚠️⚠️ **payload 에 가격을 싣지 않는다** — 싣는 순간 서명·비밀키·만료·재생방지가 따라오는데, 담기는 값이 전부 이미 클라 소유·조작 가능하고 청구 정본은 서버 견적/주문이라 **지키는 것이 0** 이다. 예외는 복귀 host(`o`) 하나이고, 그건 나중에 성공 화면의 **href 로 렌더**되므로 서명이 아니라 **`GET /v1/storefront/resolve` 재검증**으로 막는다(스킴은 클라가 `https://` 로 조립, 디코더가 대문자·포트·경로·`//evil.com`·`javascript:` 를 구조적으로 거부, 실패·미등록은 전부 "저장 안 함" — **fail-open 금지**). ⚠️⚠️ **`SessionSyncMount`(`layout.tsx:77`)은 `{children}` 앞 형제라 effect 가 페이지보다 먼저 돈다** — 옛 카트로 `merge` 를 동시에 쏘고 서버 프로필 국가로 `store.country` 를 덮어, 페이지 안에서 순서를 아무리 지켜도 못 푼다. 그래서 `useSessionSync` 에 **`usePathname() !== '/handoff'` 스위치**를 넣고 `/handoff` 가 같은 일(프로필 국가 **await** 업로드 → `cart.merge` → `replaceCart` → `repriceCartForCountry`)을 직접 한다. ⚠️ "이미 동기화됨" 플래그는 **일부러 안 뒀다** — `/checkout` 에서 훅이 한 번 더 도는 게 `sameCart` early-return 으로 no-op 이면서 핸드오프 merge 실패 시 **자가치유**가 되기 때문(플래그를 두면 부분 실패가 그 문서에서 영구 차단된다). ⚠️ `commitCountry()` 를 쓰지 않는 이유도 같다 — 그쪽 프로필 업로드는 fire-and-forget 이라 캐시된 `user.country` 가 스테일인 채 넘어가 `/checkout` 에서 국가가 되돌아간다. ⚠️ 복원에 **`addToCart` 를 쓰지 않는다**(담기 비콘이 재발사돼 `cartAdds` 가 두 배 — 순담기자는 flip-once 라 **전환율만 조용히 망가진다**). ⚠️ **`PUT /v1/cart/merge` 는 브랜드당 5개 상한을 검사하지 않아**(상한은 `cart.upsert` 와 주문 생성에만 있다) 합친 뒤 `brandRemainingCapacity` 로 클램프해야 결제 버튼에서 raw 400 이 안 뜬다. ⚠️ `visitorId` 는 klow.kr 에 **없을 때만 심고, 있으면 덮지 말고** `sessionStorage['klow-handoff-vid']` 에 둬 **주문 생성만** `handoffVisitorId() ?? peekVisitorId()` 를 쓴다(퍼널 원장이 `(brandId, date, visitorId)` 라 다른 vid 로 들어가면 **그 브랜드의 결제 단계가 영구 0**). ⚠️ 결제 후 브랜드 도메인 카트 정리는 `/checkout/redirect` 가 `removeProducts` 와 **같은 블록**에서 `setBrandReturn(…?purchased=)` 를 붙이는 방식이고(그 블록이 "결제 성공 + 이 상품들이 팔렸다"를 아는 유일한 지점), 저장값이 **다른 오리진일 때만** 붙는다 — `isCustomDomain()` 은 자기 `location.host` 를 보는 함수라 여기선 못 쓰고, 값 기준 판정 `isExternalHref()` 를 쓴다. ⚠️ **한 벌만 두기로 한 것 3가지**(두 번째 사본을 만들지 말 것): 서버 카트 머지 절차 `lib/cart-sync.ts`("묘비는 서버가 삭제를 확인했을 때만 비운다"가 `useSessionSync`·`/handoff` 로 갈라지면 한쪽만 고쳐진다) · "남의 오리진인가" `lib/host.ts isExternalHref`(`?purchased=` 부착과 성공 화면 `<Link>` 분기가 같은 값을 `startsWith('https://')` 와 host 비교로 따로 보고 있었다) · 주문이 쓸 방문자 토큰 `visitorIdForOrder`(`handoffVisitorId` 를 export 하지 않아 담기 비콘 등에 끼워 넣는 두 번째 호출부가 **구조적으로** 불가능하다). ⚠️ 본 도메인 판정은 **존 접미사 규칙**(`host === apex || host.endsWith('.'+apex)`)이라 `www.`·`staging.klow.kr` 이 자동으로 덮이고, 서버 `domain-host.ts` 가 `klow.kr`·`*.klow.kr` 을 커스텀 도메인으로 **거부**하는 것과 맞물린다. ⚠️ **`npm run i18n:fill` 은 값이 en 과 같은 로케일 문자열을 "누락"으로 보고 다시 기계번역한다** — 이번에 `labels.category` 큐레이션 값 3개(`id.mist`/`vi.toner`/`vi.serum`)가 `Kabut`·`Huyết thanh`(혈청)로 되돌아가 손으로 복구했다. **fill 을 돌릴 때마다 그 셋을 확인할 것.** 마이그레이션·서버 변경 **없음**(`klow_web` 단독). 자세히는 [`docs/plan/custom-domain/implementation-plan.md`](../plan/custom-domain/implementation-plan.md) §3.
