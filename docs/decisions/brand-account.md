## Instagram 연동 (댓글→DM, 2026-07)

브랜드가 klow_brand **인스타그램** 탭에서 자기 IG 비즈니스/크리에이터 계정을 연동("Instagram API with **Instagram Login**" — Facebook 페이지 불필요)하고, 자기 포스팅 댓글에 **브랜드관 링크(klow.kr/{slug})가 담긴 메시지 템플릿**으로 **일괄 DM(private reply)** 을 보내 댓글 단 사람을 브랜드관으로 유입시킨다. DM 은 댓글 작성자가 먼저 DM 한 적이 없어 일반 DM 불가 → **private reply(`recipient:{comment_id}`)가 유일 경로**(댓글당 평생 1회 · 댓글 후 7일 이내 · 750/hr per-account). 60일 장기토큰은 AES-256-GCM(`META_TOKEN_ENCRYPTION_KEY`) 암호화 저장 + **`InstagramRefreshCron`(매일 KST 03:00)이 만료 전 롤포워드 → 재인증 없이 영구 연동**(브랜드 로그인 세션과 무관). 멱등성은 `InstagramReply.commentId @unique`. 공동작업 게시물은 publish 계정만 접근 가능(collaborator 초대분은 댓글 빈 상태). **⚠️ 실제 브랜드 사용은 Meta App Review + Business Verification(Advanced Access) 통과 후** — 승인 전엔 앱 tester role 테스트 계정만 동작(코드는 동일). 모델 `InstagramConnection`/`InstagramTemplate`/`InstagramReply`. 자세히는 [`docs/reference/instagram-integration.md`](../reference/instagram-integration.md) + [`docs/server/modules/instagram.md`](../server/modules/instagram.md).

## 랜딩 상담 문의 폼 (2026-08-10)

klow_brand 랜딩 최종 CTA "상담 문의"가 `mailto:team@klow.kr` 링크에서 **모달 폼**으로 바뀌었다(`klow_brand/src/components/ContactModal.tsx` — 브랜드명·연락처·이메일 필수 + **문의내용은 선택**). 제출은 공개 엔드포인트 `POST /v1/contact-inquiries`(신규 `klow_server/src/modules/contact/`, 가드 없음 + `THROTTLE_TIGHT` 5회/분)로 가고, 서버는 **저장하지 않고** `EmailService.sendBrandContactInquiry` 로 `CONTACT_INBOX_EMAIL`(기본 `team@klow.kr`)에 Resend 메일만 보낸다 — 문의자 이메일은 `replyTo` 에 실려 받은편지함에서 바로 회신된다(`send()` 에 `replyTo?` 를 이때 추가). 저장이 없으므로 **발송 실패는 500 으로 그대로 올린다**(조용히 성공을 반환하면 문의가 유실). ⚠️ 네 필드 전부 미인증 공개 입력이라 메일 템플릿은 모든 값에 `escapeHtml()` 을 적용하고 `\n → <br>` 치환은 **이스케이프 후**에 한다. 모달은 CTA 클릭(`data-contact-cta` 위임) 외에 **딥링크 `?contact=1`** 로도 열려 블로그·SNS 에 `https://brand.klow.kr/?contact=1` 을 그대로 붙일 수 있다(`?login=1`·`?signup=guide` 와 동일 규약). ⚠️ 랜딩의 로그인 자동 `/studio` 리다이렉트는 `?contact=1` 일 때 **건너뛴다** — 안 그러면 로그인된 브랜드가 블로그 링크를 눌러도 모달을 보기 전에 튕긴다. 마이그레이션·DB 변경 없음. 자세히는 [`docs/server/modules/contact.md`](../server/modules/contact.md).

## 회원가입 → 브랜드 주소(slug) 순서 뒤집기 (2026-08-24)

예전엔 랜딩 "글로벌 진출하기" 가 **`SlugModal` 로 영문 브랜드명(URL slug)부터** 받아 `sessionStorage`(`klow_brand_pending_slug`)에 넣고, 그 값을 가입 payload(`/v1/brand/auth/{signup,phone/signup}` · 구글 `?slug=`)에 실어 **가입 트랜잭션 안에서 Brand draft 를 함께** 만들었다. 이유는 `BrandUser.brandId === null` orphan 차단이었다. 지금은 **가입을 먼저 끝내고**, 세션이 생긴 뒤 **`/start` 페이지**(모달 아님)에서 slug 를 받아 `POST /v1/brand/applications/init-draft` 로 만든다. ⚠️ **klow_brand 단독 배포 — 서버 변경·마이그레이션·라우트 추가 0건**: 세 가입 스키마의 `slug` 는 원래부터 `.optional()` 이고 `initDraft` 도 "slug 가 안 실려온 엣지/legacy 안전망"으로 이미 있었다(둘 다 서버에 그대로 남아 있고 klow_brand 만 안 쓴다 — 구 프론트가 배포 창에 남아도 안전). ⚠️⚠️ **그 대가로 모든 신규 계정이 `brandId === null` 로 태어나므로, 그 창을 닫는 게 이 변경의 절반이다** — 게이트는 **`(authed)/layout.tsx` 한 곳**뿐이고 `BrandSessionUser.brandId` 를 본다(그전까지 klow_brand UI 가 안 쓰던 필드). 가입 경로가 3개(전화 OTP·구글 OAuth·이메일)에 "중도 이탈 후 재로그인"까지 있어 **각 경로가 목적지를 알게 하면 반드시 하나가 빠진다**; 특히 **구글은 서버가 `BRAND_FRONTEND_URL`+`returnTo` 로 리다이렉트해 클라가 목적지를 통제하지 못한다** — 그래서 세 경로 전부 종전처럼 `/studio` 로 착지시키고 게이트가 흡수한다. ⚠️ 게이트는 **`validated`(=`/me` 가 이번 마운트에서 실제로 끝남)를 함께 봐야 한다** — `useBrandSession` 이 localStorage 로 세션을 낙관적 시드하므로 그것만 믿으면 다른 브라우저에서 브랜드를 만든 사용자가 `/start` 로 헛튕긴다(랜딩의 `/studio` 자동 이동이 같은 이유로 이미 `validated` 를 본다). ⚠️⚠️ **그 대가로 반대 방향 구멍이 열리므로 판정이 비대칭이다 (2026-08-25 수정)** — `ready`(=`!isPending`)는 localStorage seed 만으로 켜지는데 `needsBrandSetup` 은 `validated` 를 요구하니, 그 사이 프레임엔 `redirecting` 이 false 라 **brand 없는 계정이 `/me` 를 기다리는 동안 저장이 안 되는 studio 를 한 번 본다**(가입 직후엔 `setSession` 이 방금 seed 를 써 두므로 **매번** 그렇다 — 실제로 `skeleton → studio 깜빡 → /start` 로 보였다). 그래서 `unsureNoBrand = ready && authed && !validated && user?.brandId === null` 을 **렌더 홀드에만** 더한다 — seed 가 "brand 없음"이라고 말하면 스테일할 수 있으니 `/start` 로 **보내지는 않되**(위 헛튕김 방어 유지) 확정될 때까지 아무것도 그리지 않고, seed 에 `brandId` 가 있으면 종전대로 낙관적 렌더라 일반 사용자는 대기가 늘지 않는다. ⚠️ 리다이렉트 판정(`useEffect`)에는 넣지 말 것 — 넣는 순간 스테일 seed 가 `/start` 로 보내는 그 버그가 돌아온다. 리다이렉트 대기 중엔 `children` 을 안 그린다 — brand 있는 사용자에게 슬러그 폼을 한 프레임 비추거나, brand 없는 계정에게 **아무것도 저장되지 않는 무반응 스튜디오**(`useBrandAutoSave.applyBrandPatch` 가 `if (!brand) return`)를 보여주게 된다. ⚠️⚠️ `/start` 의 `initDraft` 성공 처리는 **`patchSession({...user, brandId})` 를 동기적으로 먼저** 해야 한다 — `invalidateSession()` 만 쓰면 `/me` refetch 를 기다리는 프레임에 게이트가 아직 `null` 을 보고 `/studio` → `/start` 로 되튕겨 **무한 루프**가 된다(`useBrandAutoSave.onSuccess` 가 invalidate 대신 `setQueryData` 를 쓰는 것과 같은 판단). 반면 `qk.brandApplication` 은 **invalidate 로 둔다** — `init-draft` 응답은 raw Brand 라 `APPLICATION_INCLUDE`(products·submittedBy)가 없어 캐시에 심으면 shape 이 어긋난다. ⚠️ slug 충돌은 **가용성 검사와 제출 사이에** 생길 수 있어 최종 판정이 서버 409(`이미 사용 중인 링크입니다`)다 — 토스트만 띄우고 페이지에 머문다. ⚠️ 하드 게이트라 `/start` 에 **로그아웃 탈출구**가 필요하다(설정 페이지와 같은 optimistic logout). ⚠️ 새 최상위 `(authed)` 라우트라 **`src/middleware.ts` matcher 에 `/start/:path*` 를 넣어야** 미인증 접근이 빈 화면을 한 번 안 그린다. 함께 정리된 것: `SlugModal.tsx` **삭제**(`useSlugAvailability`·`CheckMessage` 의 유일 소비자였고 `/start` 로 이전), `/signup`(이메일) 의 **pendingSlug 하드 가드 제거**(그전엔 slug 없이 열면 `/?signup=guide` 로 되돌려 보냈다), studio 의 `pendingSlug`+`initDraft` 자동 호출 안전망과 `useBrandAutoSave` 의 `pendingSlug` 인자 제거, `lib/constants.ts` 의 `PENDING_SLUG_STORAGE_KEY`/`persistPendingSlug`/`peekPendingSlug` 삭제, `api.ts` 의 `signup`/`phoneSignup` payload 와 `googleStartUrl` 에서 `slug` 제거. ⚠️ **`SignupGuideModal` 은 삭제하지 않았다** — `?signup=guide` 를 아직 3곳이 생산한다(`LoginModal` 미가입 번호 · `ForgotPasswordFlow` 미가입 이메일 · **klow_server 구글 `mode=login` 콜백**); 카피만 "브랜드 주소 입력" → "회원가입 시작"으로 고쳤고 `onConfirm` 이 이제 `SignupModal` 을 연다. 부수 효과(의도된 개선): 프로덕션에 남아 있던 `brandId === null` orphan 계정이 다음 로그인에 `/start` 로 유도되어 자동 복구된다. 자세히는 [`docs/server/modules/brand-auth.md`](../server/modules/brand-auth.md).

## `/start` 2단계 — 업종(취급 품목) 선택 (2026-08-25)

위 항목으로 `/start` 가 브랜드 주소만 받게 되면서, **EFS 송장 24-6/24-8 의 정본인 `Brand.category` 를 온보딩에서 가장 늦게 묻는** 구조가 남았다(제품 등록 진입을 가로채는 스튜디오 `categoryGate`). 순서를 뒤집어 `/start` 를 **주소 → 업종** 2단계로 만들고 `categoryGate` 와 `OnboardingCategoryView` 를 **제거**했다(브랜드관 셀렉트는 그대로 — 변경 경로는 거기 하나다). ⚠️⚠️ **1단계에서는 서버를 부르지 않는다** — brand 가 생기는 순간 `patchSession` 이 `brandId` 를 채우고 `(authed)/layout.tsx` 게이트가 `/start` → `/studio` 로 replace 해 **2단계에 도달할 수 없다**. slug+category 를 2단계 CTA 에서 `init-draft` 한 번으로 보내 원자적으로 만드는 이유가 이것이고, 같은 이유로 **스텝은 라우트가 아니라 `useState`** 다(게이트가 `pathname === '/start'` **정확 일치**라 `/start/category` 는 즉시 되튕긴다). ⚠️ **`START_FORM_ID` 원격 제출은 1단계 전용**이다 — 2단계 본문은 form 이 아니라 카드 그리드이고, `<form>` 으로 감싸면 **검색창 Enter 한 번에 브랜드가 생성된다**. 1단계 form 은 2단계에서 `hidden` 이 아니라 **조건부 렌더로 언마운트**한다(DOM 에 남은 `id` 가 유령 제출 경로가 된다). ⚠️ 기존 `onError` 의 `inputRef.current?.focus()` 는 2단계에서 **조용히 아무 일도 안 한다**(입력칸이 언마운트돼 ref 가 null) — 409/400 은 고칠 값이 1단계에 있으므로 `setStep('name')` 로 되돌린다. **카탈로그는 24장이지만 선택 가능한 건 화장품·치과재료 2장뿐**이고 나머지 22장은 '추가 예정' 표시 전용이다(`start/_components/category-catalog.ts`). ⚠️⚠️ **HS 코드를 새로 만들지 않았다** — 10자리 HSK 는 관세청 세번이라 추측할 수 없고(EFS `Service type` 을 추측했다 발급이 거절된 선례), 그래서 **prisma enum·마이그레이션·`BRAND_CATEGORY_CUSTOMS`·klow_admin·klow_web 전부 무변경**이다. 업종을 실제로 열려면 관세사/EFS 확인을 거쳐 enum + `BRAND_CATEGORY_CUSTOMS` 에 한 줄씩 넣고 카드를 `status:'coming'` → `'live'` 로 바꾼다. ⚠️ 카탈로그가 **`as const satisfies readonly CategoryCard[]`** 인 것이 커버리지 검사의 전제다 — `: readonly CategoryCard[]` 애너테이션을 달면 `LiveValue` 가 `BrandCategory` 전체로 넓어져 `CATALOG_COVERS_ALL_CATEGORIES` 가 **항상 통과**한다(서버 `BRAND_CATEGORY_CUSTOMS` 와 같은 이유·같은 패턴). 판별 유니온(`coming` 은 `value?: never`)이라 추가예정 카드를 실수로 `onSelect` 에 넘길 수 없다. ⚠️ **추가 예정 카드를 `disabled` 로 잠그지 말 것** — click 이 발화하지 않아 안내 토스트가 영영 안 뜬다(`aria-disabled` + opacity 로만). ⚠️ 서버 zod 는 `category` 를 **optional** 로 받는다 — required 면 배포 창의 구버전 klow_brand 탭이 `{slug}` 만 보내 400 을 맞는데 그 사용자는 **나갈 수 없는 하드 게이트 안**이다. 멱등 재호출은 **비어 있을 때만 채우고 절대 덮어쓰지 않는다**(덮어쓰면 이 라우트가 통관 분류의 두 번째 편집 경로가 된다). `draftBrandCreateData` 의 `category?` 도 optional 유지 필수 — `brand-auth` 가입 트랜잭션이 같은 함수를 쓴다. ⚠️ `FormPageShell` 에 **`stickyFooter`** prop 이 생겼다(기본 false) — 그 셸의 푸터는 `min-h-screen` 흐름 배치라 "화면 하단 고정"이 **본문이 짧을 때만 참**이고, 카드 24장이면 모바일에서 CTA 와 **로그아웃(게이트의 유일한 탈출구)**이 400px 밖으로 밀린다. `fixed` 가 아니라 `sticky` 라 끝까지 스크롤하면 마지막 행이 온전히 드러난다. ⚠️ 같은 셸에서 **상단 높이 판정도 `hasBar = !!topTitle || !!onBack` → `!!topTitle` 로 좁혔다** — 전자면 뒤로 버튼만 있는 스텝에서 상단이 스페이서(48/80px) 대신 바(64px)가 되어 **스텝을 넘길 때 제목이 위아래로 튄다**(모바일 +16px / 데스크탑 −16px). 바는 제목을 담으려고 있는 것이고 뒤로 화살표는 어느 쪽이든 좌측에 겹쳐 띄운다. `/signup` 은 `topTitle` 이 있어 무변경. 마이그레이션·백필 없음 · 라우트 수 불변 · cron 9개 불변. 배포 순서는 **klow_server → klow_brand**(⚠️ 서버를 브랜드보다 **먼저 롤백하지 말 것** — category 가 zod strip 되어 null 저장되는데 관문도 없어 제품 등록이 400).

## 브랜드 고객 관리(CRM) + 메일 발송 (2026-08-27)

브랜드가 시딩으로 보낸 사람들이 **어느 화면에도 "사람" 단위로 모이지 않았다** — `/v1/brand/shipments/*` 는 수령인 PII 를 주지만 **송장 단위**라 "이 사람에게 3월에도 보냈다"를 알 수 없고, `/v1/brand/seeding/links` 는 PII 를 아예 안 준다(`toClaimDTO` 에 이름·이메일·주소 없음). 신원·이력은 이미 `Order`/`OrderItem` 에 전부 있고 복제하면 동기화 코드가 생겨 곧 갈린다(`SeedingLink.recipientInstagram` 류 dormant 미러 선례). 저장하는 건 브랜드가 **직접 쓴 것**뿐이다(`BrandCrmNote` 태그·메모 / `BrandCrmTemplate` / `BrandCrmEmail` ## 주문 탭 서브탭·목록 카드를 디자인 탭 톤으로 통일 (2026-09-18)

스튜디오 `주문` 탭의 서브탭이 `shipping/ui.tsx` 의 **슬라이딩 pill**(흰 pill 이 translateX 로 미끄러지는 형태, `py-3`)이었는데, 그 active 배지가 `bg-ink` 라 **상위 탭(IdlePanel TABS)의 active 채움과 같은 톤**이어서 2단 위계가 안 읽혔다(색 덩어리가 위아래로 반복). `DesignSubTabs` 와 같은 **인셋 pill**(`bg-bg` 컨테이너 + active `bg-white` + 아이콘 + `bg-auth-obj2` 배지)로 합쳤다. ⚠️⚠️ **`DesignSubTabs` 주석의 *"shipping 의 Segmented 와는 별개 계보다. 통일하지 않는다"* 를 뒤집은 것이다** — 근거는 취향이 아니라 위 위계 문제이고, 그 주석도 함께 정정했다(한쪽만 되돌리면 두 서브탭이 다시 갈라진다). ⚠️⚠️ **라벨은 `주문 현황 / 배송 현황` → `발송 대기 / 배송 중` 으로 바꿨지만 `SubTab` 값(`'orders'` / `'shipping'`)은 그대로다** — `?navTab=` 딥링크(시딩 '배송현황 보러가기' → `ordersNavTarget`)의 계약이라 값을 바꾸면 그 진입이 조용히 죽는다. 라벨을 바꾼 이유는 상위 탭이 이미 '주문'이라 단어가 겹쳤고, 목록 내용(내가 박스를 보내야 할 건 / 이미 떠난 건)과도 어긋났기 때문이다. `SUB_TAB_ORDER` 는 슬라이딩 pill 의 `translateX` 계산 전용이었어서 **미사용**이 됐다(`shipping.model.ts` 에는 남아 있다). ⚠️⚠️ **`StatusProgress` 는 목록 카드(`ShipmentCard`)와 상세 모달(`ShipmentDetailModal`)이 공유하므로 `compact` prop 으로 갈랐고 기본값이 `false` 라 상세는 무변경이다** — 목록에서만 4단계 라벨(카드당 4개 × N장)을 지우고 진행바 아래 `현재 단계 · 실제 상태명` 한 줄로 접는다(어느 단계인지는 바 길이가 이미 말한다). **기본값을 뒤집지 말 것** — 상세는 카드가 한 장뿐이라 "다음에 무엇이 오는지"가 정보다. ⚠️ 배송 카드의 유형 라벨(우측 14px bold ink)을 이름 옆 작은 회색 배지로 내리고 **일반 주문에는 아예 달지 않는다** — 이 목록은 다수가 일반 주문이라 모든 행에 같은 글자가 박히면 순수 노이즈다(`OrderCard` 가 이미 같은 이유로 배지를 안 단다. 재고 탭의 *"기본 상태는 말하지 않는다"* 와 같은 규칙). ⚠️ `freeSeeding`/`isSeeding` 판정과 그 재료인 `settlementSum` 의존은 **그대로**다 — 고객 결제 시딩을 '무료 시딩'으로 쓰면 정산금을 받는 건을 브랜드가 포기한 걸로 읽는다. ⚠️ 발송 대기 카드의 줄 순서가 **수취인 → 제품 → 지역·날짜**로 바뀌었다 — 예전엔 국가명이 `UNITED STATES` 처럼 대문자 + `tracking-wider` 로 맨 위에 있어 카드에서 가장 먼저 읽혔는데, 이 화면에서 브랜드가 찾는 것은 누구에게 무엇을 보내는가다. 제품명도 `text-sub` → `text-ink/80 font-semibold`. ⚠️ 카드 하단 전폭 `바코드 · 발송 처리 ⌄` 줄(카드 높이의 1/3 을 먹으며 카드마다 반복)을 우측 **`발송 ⌄` 버튼**으로 옮겼다 — **글자를 지우고 아이콘만 두지 말 것**(발송 처리는 이 화면의 핵심 액션이라 어디서 하는지 알 수 없게 된다). 본문(상세 이동)과 토글은 **형제 button** 이어야 한다(중첩은 유효하지 않은 HTML 이고 클릭이 서로를 삼킨다). h3 `발송 대기 주문` 과 `탭하면 송장이 보여요` 안내는 제거했다(서브탭이 이미 같은 말이고, 안내는 한 번 알면 되는 사실을 목록 위에 상시로 띄웠다). **klow_brand 단독 · 서버·klow_web·klow_admin 무변경 · API·라우트·마이그레이션·cron 전부 불변 · 배포 순서 제약 없음.**
