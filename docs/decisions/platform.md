## 어드민 대시보드 개편 + 브랜드 접속 추적 (2026-08)

홈 KPI 가 **구조적으로 우상향만 보이던 것**을 걷어냈다 — 주별 **누적** 선차트(`/admin/stats/export-weekly`)와 거기서 파생된 `avgWeeklyGrowthPct` 를 제거하고, **수출·구독 둘 다 주별 비누적 막대 + 4주 이동평균**(`/export-trend`, `/subscription-trend`, 최근 26주, 공용 컴포넌트 `WeeklyTrendChart`)으로 교체했다. **마지막 주는 아직 진행 중이라 `partial:true` + `ma:null`** 로 내려 막대를 연하게 칠하고 평균선을 끊는다(안 그러면 미완성 주가 늘 하락으로 오독된다). 라벨 정정: "누적 총수익"→**브랜드 구독매출**(`revenueTotalKrw` — 구 값은 건당 ₩1,500 하드코딩 시딩 이익이 섞여 있었고 그 상수·파생 `total*Krw` 는 폐기), "가입 브랜드"(실제로는 `BrandUser.count()`)→**구독중인 브랜드수**(`activeCount`, `brandCount` 필드 삭제). 신규 **`/admin/stats/brand-activity`** 는 구독중(active/past_due) 브랜드의 마지막 활동으로 활성(≤7일)/저활성(8~30일)/휴면(>30일 또는 기록 없음) 세그먼트 + "관리 필요" 목록을 낸다. ⚠️ **활동 소스는 브랜드가 직접 만든 타임스탬프 8종으로만 한정**하고 `Promotion.updatedAt`(**방문자 클릭**이 `clickCount` 를 올리며 bump)·`Product.updatedAt`(어드민 편집 + `backfill:product-tags-english` 가 전 제품 bump 한 전례)·`Brand.updatedAt`(어드민 승인/편집)·`SeedingClaim`(바이어 행동)은 **의도적으로 제외** — 넣으면 브랜드가 아무것도 안 했는데 활성으로 뒤집힌다. 접속 축은 `getSession()` 이 5분 스로틀로 찍는 **`BrandUser.lastSeenAt`** 이 정본이다(`BrandSession.lastSeenAt` 도 함께 찍지만 세션은 만료 시 하드 삭제 + TTL 7일이라 그것만으론 "20일 전 접속"과 "미접속"이 구분 안 됨). 마이그레이션 `add_brand_last_seen` 은 **추가 전용이라 롤링 안전 · 백필 불가(전진 채움만)** — `lastLoginAt: null` 은 미접속이 아니라 데이터 없음이라 UI 가 집계 시작일(`loginTrackingSince`)을 대신 표시한다. 자세히는 [`docs/server/modules/stats.md`](../server/modules/stats.md).

초기 TikTok형 콘텐츠 커머스 축이던 **크리에이터·릴스 영상**을 3개 레포에서 전면 삭제했다. 서버 `modules/creators`·`modules/videos`(라우트 15개: `/admin/creators*`, `/v1/creators*`, `/admin/videos*`, `/v1/videos*`) + 호출자가 0건이던 `GET /admin/stats`, 어드민 `크리에이터`·`릴스 영상` 탭(+`CreatorForm`/`CreatorEditor`/`VideoForm`/`CreatorPreviewPanel`/`ProductPicker`), klow_web `/discover`·`/feed`·`/videos`·`/creator/[id]`(+훅 7개·`components/{video,creator}`·PDP 의 "Videos featuring this product" 섹션)이 대상이다. 하단 탭바는 **shop/cart/my 3탭**으로 줄었고 온보딩 국가 모달 자동 노출도 `/shop` 한 곳만 남았다. ⚠️ **이름이 겹치는 생존자 3종**: `/v1/brand/creators`(=`curated-influencers` 모듈, klow_brand 크리에이터 찾기 + 어드민 인플루언서 탭), `Product.videoClipUrl`·업로드 `kind:'video'`(제품/브랜드 미디어), klow_web `components/discover/{RecommendedProducts,SectionHeader}`+i18n `discover.recommended.*`(`/shop` 추천 섹션 — 폴더명만 discover 다). `common/validation/creator.ts` 는 큐레이션 스키마만 남아 **`curated-influencer.ts` 로 rename**. 예약 슬러그(`discover`/`feed`/`videos`/`creator`)는 **일부러 남겼다** — 풀면 브랜드가 선점한다. 마이그레이션 `remove_creators_videos` 는 `Creator`/`Video`/`VideoProduct` **DROP TABLE 이라 롤링 배포 비안전**(단일 레플리카 컷오버) + 데이터 영구 삭제. 배포 순서는 프론트 2개 → 서버 코드+마이그레이션.

## 컨시어지(concierge) 기능 제거 (2026-08-11)

"아마존에도 없는 K-뷰티를 대신 구해준다"는 초기 요청 폼(사진/제품명/브랜드/메모 → 어드민이 상태만 pending/replied/completed 로 바꾸는 read-mostly 흐름)을 3개 레포에서 전면 삭제했다. 서버 `modules/concierge`(라우트 5개: `POST /v1/concierge-requests` 공개 + `/admin/concierge-requests` GET·GET :id·PATCH·DELETE) + `common/validation/concierge.ts`, 어드민 `컨시어지 요청` 탭(+`lib/api/concierge.ts`·`lib/concierge-status.ts`), klow_web `/concierge`·`ConciergeBanner`(`/shop` 상단 배너)·i18n `concierge` 네임스페이스가 대상이다. **문의 창구는 `/customer-center` 로 단일화** — 로그인 화면의 "비밀번호 재설정"·"로그인이 안 되나요?" 링크가 `/concierge` 를 가리키고 있어 거기로 옮겼다(문구·i18n 키는 그대로). ⚠️ **klow_web `api.upload` 도 같이 제거**했다 — 유일한 호출자가 컨시어지 사진 업로드였고, 공개 웹앱이 `/admin/upload` 를 치는 유일한 경로이기도 했다(어드민·브랜드 업로드는 무관). 예약 슬러그 `concierge` 는 **일부러 남겼다**(klow_web·klow_server 의 `reserved-slugs.ts` 두 파일 동기 유지 — 풀면 브랜드가 `klow.kr/concierge` 를 선점한다). 마이그레이션 `remove_concierge` 는 `ConciergeRequest` **DROP TABLE + `ConciergeStatus` DROP TYPE 이라 롤링 배포 비안전**(단일 레플리카 컷오버) + 데이터 영구 삭제. 다른 모델의 relation 참조는 0건이라 연쇄 수정 없음. 배포 순서는 프론트 2개 → 서버 코드+마이그레이션.

## 어드민 컨택트 — 전 브랜드 시딩 수령인·바이어 조회 (2026-09-04)

브랜드가 시딩으로 접촉한 인플루언서·바이어의 신원·연락처·접점 이력이 DB 에 전부 있는데 **KLOW 쪽에는 그걸 "사람" 단위로 모아 보는 화면이 없었다**. 기존 어드민 `/customers`(고객 > 회원)는 **`User` 테이블 전용**이라 게스트인 시딩 수령인이 **한 명도 안 뜨고**, 같은 파생 로직을 가진 `brand-crm`(klow_brand `/crm`)은 **브랜드가 자기 고객만** 본다. 신규 탭 `klow_admin /contacts`(고객 > **컨택트**)를 붙였고 **읽기 전용**이다. ⚠️⚠️ **고객 행을 저장하지 않는다** — `Order`/`OrderItem`/`SeedingClaim`/`ManualSeedingRecord` 에서 파생하므로 **스키마·마이그레이션·백필·cron 전부 불변**이고 배포 즉시 과거 데이터 전부가 뜬다(실측 dev 190명). 동일인 판정 사다리(`e:` → `p:` → `a:`)·수기기록 연락처 추출·브랜드 귀속·시딩 제품명 파생을 **전부 기존 순수 함수로 재사용**해 Nest 모듈 배선 변경이 0 이다(모듈 31개·cron 10개 불변). ⚠️⚠️ **같은 사람은 브랜드를 가로질러 한 행**이고(접점 브랜드는 `brands[]` 로 나열 — "A·B·C 가 다 보냈다"가 이 기능의 값이다) 공개 id 는 `customerIdOf(ADMIN_CONTACT_SCOPE='*admin*', key)` 라 **브랜드 CRM 의 id 와 다르다**(스코프가 다르니 당연하고 그게 의도다 — 두 화면 사이에서 id 를 넘기지 말 것). `customerIdOf` 첫 인자명을 `brandId` → `scope` 로 **순수 rename** 했다(기존 호출부·스펙 무변경). ⚠️⚠️ **DB 왕복은 2단이고 그 이상으로 늘리지 말 것.** 1단(7개 병렬) `order`·`product`·`brand`·`manualSeedingRecord`·`shippingCountry`·`user`·`seedingLink` → 2단(3개 병렬) `orderItem`∥`seedingClaim`∥`shipment`. ⚠️ **"쿼리 7개 = 왕복 1단"이 아니다** — `relationJoins` 프리뷰가 꺼져 있어 Prisma 가 relation 을 부모 뒤에 따로 쏜다(실측 총 10쿼리/깊이 2). 그래서 중첩을 한 겹 더 파면 직렬 단이 는다 — `seedingClaim.link` 를 중첩했다가 3단이 됐고 링크를 1단 전량 읽기로 뺐다(390행·29KB). 그래도 brand-crm 보다 한 단 적다(저쪽은 주문 where 가 `productIds` 에 의존해 `product`→`order` 가 직렬인데 어드민은 브랜드로 안 좁힌다). 참조 테이블 다섯은 **`where` 없이 전량** 읽는다(`in` 절을 걸면 주문 결과를 기다려야 해 왕복이 한 단 는다). `decorate()` 는 **DB 를 안 치는 순수 함수**다. 실측 워엄 조회 0.7~1.0초. ⚠️⚠️ **주문 필터·채널 분할의 정본은 `orders/contact-population.ts` 한 곳**이다(`CONTACT_ORDER_WHERE` + `contactChannelOf`) — 예전엔 brand-crm 과 복사본 두 벌이 "같은 값이어야 한다"는 **주석으로만** 묶여 있었고, 갈리면 두 화면이 같은 사람을 놓고 다른 모집단을 보게 된다(`item-brands.ts`·`brand-selects.ts` 가 이미 같은 병으로 만들어진 파일이라 같은 처방을 썼다). `SETTLEABLE_ORDER_WHERE` 상속 금지(무가 시딩이 핵심 모집단). ⚠️ 채널 3분할은 **`isSeeding` 을 먼저** 본다(`Order.channel` 기본값이 `web` 이라 channel 만 보면 시딩 수령인이 일반 구매자에 섞인다). ⚠️ 스코프별로 달라도 되는 값(스캔 상한 5000↔10000)은 올리지 않았고, `common/validation/*` 의 채널 zod enum이 별개인 건 **`common/` 이 `modules/` 를 import 할 수 없다는 구조 규칙** 때문이지 선택이 아니다. ⚠️ 브랜드 귀속은 `orders/item-brands.ts` 에 **역방향 헬퍼 `itemBrandIdOf` 를 추가**하고 기존 `resolveItemBrands` 도 그걸 쓰게 고쳤으며(안 그러면 "규칙을 한 번만 적는다"가 그 파일 **안에서** 깨진다), **`Shipment.brandId`(발급 시점 동결) 축을 함께** 본다(빼면 제품이 하드 삭제된 과거 고객의 브랜드가 빈칸). ⚠️⚠️ **회사메일 판정(`customers/email-domain.ts`)은 접미사 매칭을 쓰지 않는다** — `mail.*`/`yandex.*` 류 suffix 규칙은 `mail.acme.com`(실재 회사 호스트)을 개인메일로 오분류해 **바이어를 목록에서 지운다**. 명시 집합만 쓴다(~250개). ⚠️⚠️ **이건 사실이 아니라 추정**이라 학교(`.ac.kr`)·소국가 ISP·개인 도메인이 전부 `corporate` 로 잡힌다 → 화면 라벨이 "회사메일"이 아니라 **"도메인 메일"** 이고 상세에 "바이어 추정(확정 아님)"을 병기한다. **도메인 그룹**(`domains[]`, corporate 만 상위 50)과 **국가 목록**(`countries[]`)은 ⚠️ 모집단이 **그 축을 뺀** 결과다(`applyFilters` 가 도메인·국가를 아예 안 보고 `narrowByFacets` 가 마지막에 적용한다 — 적용 후로 세면 하나를 고르는 순간 선택지가 그것만 남아 되돌아갈 수 없다). ⚠️ 국가를 서버 facet 으로 내리는 이유는, 화면이 **현재 페이지 50행에 보이는 국가**로 datalist 를 만들면 필터를 거는 이유("그 국가가 지금 안 보여서")와 정면으로 어긋나기 때문이다. ⚠️ **KLOW 회원 여부는 `Order.userId` 가 아니라 이메일로 조인**한다(전자만 보면 게스트로 결제한 회원이 통째로 비회원이 된다) — `User` 전량 읽기는 `USER_SCAN_CAP` 으로 막고 닿으면 타깃 조회로 전환(왕복 +1단). ⚠️ **시딩 타임라인 제품명은 통관 별칭이 아니라 진짜 제품명**이다(`SEEDING_ITEM_NAMES_SELECT` + `seedingItemNames()` + `displayLines()` — brand-crm 에는 아직 이 처리가 없어 거기선 `Korean Skincare Toner` 가 뜬다). ⚠️ **목록 응답에 주소가 없다**(PII 최소화) — 상세·내보내기에만. `decorate` 에 주소를 넣는 순간 목록 API 가 전 컨택트 주소를 내려보낸다(회귀 스펙이 잠근다). ⚠️ 절단 캡 10000, 닿으면 `truncated:true` + 배너 — 스캔이 `createdAt desc` 라 **가장 오래된 쪽**이 잘리고 그 상태의 `sort=purchase|contacts` 는 최근 구간 위의 정렬이다. **권한**: 조회는 AdminGuard, **내보내기만 SuperAdminGuard** 이고 ⚠️⚠️ **내보내기가 GET 이 아니라 POST 인 이유는 감사 로그**다(`AdminAuditInterceptor` 가 GET 을 기록하지 않는데 플랫폼 전체 PII 대량 반출이라 흔적이 남아야 한다 — 인터셉터는 요청 body 만 기록하고 `@Res()` 스트림 응답은 안 읽어 안전하다). ⚠️ 정적 `export` 를 `:id` **앞에** 선언(`shipping-countries/export` 선례), 없는 id 는 `Forbidden` 이 아니라 **`NotFound`**(존재 열거 차단). ⚠️ 시트명 `컨택트` 를 **`EXPORT_SHEET_NAMES` 에 등록**했다(빠뜨리면 다른 탭 업로드에서 첫 시트 폴백으로 먹힌다) — 그 레지스트리는 원래 `modules/shipping/xlsx-grid.ts` 안에 있었는데 컨택트가 문자열 하나 때문에 shipping OOXML 파서를 통째로 import 하게 돼 **이름만 `common/xlsx-sheet-names.ts` 로** 올렸다(파서·라이터는 shipping 소유 그대로). ⚠️ 엑셀 날짜는 ## 현지 통화 표시 — `enabled` 게이트 제거 + 사우디 새 기호 (2026-09-11)

사우디를 골라도 가격이 `SAR` 가 아니라 **USD** 로 보였다. 데이터는 이미 맞았다 — `SA.currencyCode='SAR'` 도 `CurrencyFxRate['SAR']`(3.75)도 있었고, `CurrencyService.publicPayload()` 의 **`where: { enabled: true }`** 하나 때문에 응답에서 빠져 klow_web `useLocalPrice` 의 `countryCurrency[country] || 'USD'` 로 떨어졌다. ⚠️⚠️ **`enabled` 는 배송지원 화이트리스트이지 통화 표시 축이 아니다.** 국가 선택(온보딩·브랜드관·부스 QR)은 이미 `enabled` 를 안 본다 — 그 국가는 배송지가 아니라 **가격 기준국**이라서다. 그래서 "고를 수 있는 국가"와 "통화를 아는 국가"가 어긋나 있었다(실측 234개국 중 enabled 14 / 통화 보유 128). klow_brand 스튜디오 목업도 같은 payload 를 써서 브랜드가 국가별 판매가를 정할 때 같은 증상을 봤다. 필터를 빼서 payload 가 14 → **128개국**(+1.4KB)이 됐고 **아랍권 13개국이 함께 해결**된다(AE→AED, QA→QAR …). 노출 위험은 없다(통화코드는 공개 사실이고 금액이 아니다) — FX 행이 없는 통화가 섞여도 클라가 `rate > 0` 일 때만 현지통화로 그려 USD 로 안전하게 폴백한다. 회귀 잠금 `currency/__tests__/public-payload.spec.ts`(되돌리면 2건 실패 · 스텁도 where 를 실제로 적용해 무시하면 통과하는 일이 없다). **같은 날 SAR 만 새 기호 `⃁`(U+20C1)로 바꿨다.** ⚠️ `Intl.NumberFormat` 은 이 기호를 **절대 주지 않는다** — Unicode 17.0(2025-09) 신규라 CLDR 이 아직 **alternate 로 분류**해 `currencyDisplay` 를 뭘 줘도 `SAR` 문자열만 나온다. 그래서 `klow_web/src/lib/format.ts` 의 **`SYMBOL_OVERRIDES`** 가 직접 넣는다 — 그 파일의 *"겹침 판정은 하드코딩 목록이 아니라 계산"* 원칙에 대한 **의도된 예외**이고, CLDR 이 primary 로 승격하면 이 표에서 SAR 을 지우면 된다. ⚠️ 치환은 `formatToParts` 로 **통화 조각만** 바꾼다(문자열 `replace` 는 금액 안의 같은 문자열까지 건드리고, 기호 위치·CLDR 구분 공백 **NBSP** 를 보존해야 한다). ⚠️⚠️ **오버라이드와 웹폰트는 한 쌍이고 한쪽만 지워도 빌드가 통과한다** — 폰트를 지우면 기기 폰트에 U+20C1 글리프가 없어 **두부(□)** 가 되고(실측: 웹폰트 없이 그리면 렌더 폭이 두부와 **정확히 같다**), 오버라이드를 지우면 조용히 `SAR` 로 되돌아간다. 폰트는 `public/fonts/saudi-riyal.woff2`(1.2KB, SIL OFL — emran-alhaddad/Saudi-Riyal-Font)를 **자체 호스팅**한다(CDN 직링크는 가용성·프라이버시 의존). ⚠️ `@font-face` 에 **`unicode-range: U+20C1`** 이 반드시 있어야 한다 — 빼면 글리프 하나짜리 폰트가 본문 전체의 첫 후보가 된다. ⚠️ **`SYMBOL_OVERRIDES` 에 다른 통화를 추가하지 말 것** — CLDR 이 이미 좋은 기호를 주는 통화(`Rp`·`฿`·`₸`)를 덮으면 그 파일이 경고하는 "밋밋한 퇴보"를 손으로 다시 만든다(AED 는 일부러 그대로 `AED` 다). ⚠️ klow_brand `src/lib/currency.ts` + 같은 폰트가 **의도된 크로스 레포 미러**다(목업과 손님 화면 표기가 갈리면 안 된다). 회귀 잠금은 **`npm run check:currency-symbol`**(klow_web 은 테스트 러너가 없어 tsx 순수 함수 — `check-handoff`·`check-address`·`check-countries` 와 같은 형태). ⚠️⚠️ 이 가드를 처음 썼을 때 **globals.css 의 주석이 `unicode-range: U+20C1` 을 인용하고 있어서 선언을 지워도 통과했다** — 지금은 주석을 먼저 걷어내고 `@font-face` 블록 **안**만 보며, 본문 스택 검사는 그 블록을 **뺀 나머지**에서 한다(안 그러면 `@font-face` 자신의 `font-family` 선언에 속는다). **마이그레이션·백필·라우트·cron 전부 불변.** 배포 순서는 **klow_server → klow_web → klow_brand**(서버가 먼저면 구 프론트는 영향 0). 자세히는 [`docs/server/modules/currency.md`](../server/modules/currency.md).

## 바텀시트가 소프트 키보드에 가리던 버그 (2026-09-11)

국가 선택 모달에서 검색하려고 입력창을 누르면 키보드가 올라오면서 시트 아래쪽이 **키보드 뒤로** 들어가 결과 목록이 안 보였다. 원인은 `position: fixed; inset-0` 이 **레이아웃 뷰포트** 기준이라 키보드가 떠도 줄지 않는 것이다(`max-h-[90vh]` 의 `vh` 도 같다). 실측(430×932 · 키보드 500px): 시트 739px 중 **500px(68%)** 가 키보드 뒤로 들어갔다. 신규 훅 **`klow_web/src/hooks/useVisualViewportBox.ts`** 가 `window.visualViewport` 의 `height`·`offsetTop` 을 구독해 컨테이너에 씌우고, 시트 `max-h` 를 `vh` → **`%`**(=보이는 영역 기준)로 바꿨다. 적용 대상은 **검색 입력이 있는 바텀시트 2개** — `OnboardingModal`(국가 선택)과 `CountryPicker`(체크아웃·시딩 공용, `autoFocus` 라 열자마자 키보드가 떠 더 심했다). `SeedProductModal` 은 입력이 없어 대상이 아니다. 키보드가 닫힌 상태의 높이는 종전과 동일하다(739px 무변화). ⚠️⚠️ **viewport meta 의 `interactive-widget=resizes-content` 로는 못 고친다** — iOS Safari 가 지원하지 않고(Chromium 전용) 하단 탭바 등 앱 전역 fixed 요소까지 같이 움직인다. ⚠️ **`offsetTop` 을 함께 읽어야 한다** — iOS 는 키보드가 뜰 때 레이아웃 뷰포트 안에서 시각 뷰포트를 스크롤시켜서, 높이만 맞추면 시트가 화면 밖으로 밀린다(`scroll` 이벤트도 같은 이유로 구독한다). ⚠️ 미지원 브라우저·SSR 은 `null` 을 돌려주고 호출부가 종전 CSS(`inset-0`)를 그대로 쓴다. **klow_web 단독 · 서버 변경 없음.**

## 자사몰 URL 분석(`analyze-homepage`) + Playwright 제거 (2026-09-15)

브랜드가 자사몰 홈페이지 URL 을 넣으면 서버가 그 페이지를 긁어(HTTP fetch → SPA 면 Playwright chromium 폴백) 브랜드 메타 정보를 추출하던 라우트를 걷어냈다. ⚠️ **레거시 판정 근거는 둘이다**: ① klow_brand 가 **2026-08-19**(`7e0e3de` "데드코드·중복 정의 제거")에 `api.scraper.analyzeHomepage` 호출을 이미 지웠고 그 뒤 세 프론트 어디에도 호출자가 **0건**이었다(이미지 Vision 분석이 그 자리를 대신한다) ② 레포 어디에도 **chromium 설치 단계가 없어**(Dockerfile·entrypoint·CI 전부) SPA 폴백은 운영에서 **항상 503** 이었다. 함께 제거: `ssrf-guard.ts`(유일한 소비자가 이 fetch 경로였다) · `scraper.prompts.ts` 의 `SCRAPER_SYSTEM_PROMPT`/`buildUserPrompt` · `BrandDraft` 타입 · `scripts/scrape-test.ts`(+`scrape:test`) · npm 의존성 **`playwright`·`cheerio`** · `BrandScraperService` 의 `OnApplicationShutdown`. ⚠️⚠️ **되살릴 거라면 `ssrf-guard` 를 반드시 함께 되살릴 것** — 사용자 입력 URL 을 서버가 fetch 하는 순간 SSRF 표면(사내망·메타데이터 169.254.169.254)이 생기고, `common/client-ip.ts` 의 `normalizeIp` 는 hex 형(`::ffff:aabb:ccdd`)을 디코드하지 않아 **대신 쓸 수 없다**(그 파일 주석이 경고한다). 남은 두 라우트(`analyze-product`·`analyze-deck`)는 **클라가 올린 이미지 배열만** 받아 OpenAI Vision 에 태우므로 **서버가 어떤 URL 도 fetch 하지 않는다**. 스키마·마이그레이션·cron 전부 불변, **라우트 −1**. ⚠️ AWS 이전 계획에서 "Playwright 크롬을 이미지에 넣을지" 판단이 통째로 사라졌다(`docs/aws-fargate-migration.md` 갱신 완료). 자세히는 [`docs/server/modules/brand-scraper.md`](../server/modules/brand-scraper.md).
