## 제품 가격 모델 (판매가 고정 → 정산 유동 / 물류비 분리, 2026-07)

브랜드가 **원가(`Product.costKrw`) + 마진**을 입력 → **정산가(`Product.salePrice`) = 원가 + 마진**(⚠️ `salePrice` 는 이름과 달리 판매가가 아니라 정산가를 담는다 — 역사적 명명). **미핀 국가의 default 판매가(USD 센트)는 두 모델**: (1) **브랜드 신모델**(`Product.basePriceFxRate` = 저장 시점 fx 스냅샷 有) → `ceil(정산가/(1−0.05)/basePriceFxRate ×100)` — **frozenFx 로 판매가는 환율에 고정, 정산가/마진만 라이브 fx 로 유동**. (2) **어드민/legacy**(스냅샷 無) → 단일 `Product.basePriceUsd`(직접 입력). **⚠️ 2026-07-28 전환: 판매가에서 물류비를 완전히 분리**했다 — 이전엔 국가별 2kg 물류비의 절반이 판매가 마크업으로 섞여 있었지만 이제 안 들어가고, 따라서 **미핀 default 판매가는 목적국과 무관한 단일 값**이다(국가차는 핀·할인에서만). 정산 역산도 `floor(청구USD × fx × 0.95)` 로 **물류비 차감 없음**. PG 5% 는 `÷0.95`(마진 net 회수). **국가별 핀**: `ProductCountryPrice(productId, iso2, priceLocal?, discountPct, freeShipping)` — `priceLocal`(현지통화 고정 판매가)이 있으면 그 국가만 판매가 고정·정산 유동, 없으면 위 default 상속. 셋 다 기본값인 국가는 행이 없고, 저장은 **replace-all** 이라 클라가 늘 전체 배열을 보낸다. (`marginKrw` 는 구 모델 잔재로 **dormant**.) **완성도/구매 게이트 = `hasSellablePrice`**(`basePriceUsd>0 OR (basePriceFxRate≠null AND salePrice>0)`, `SELLABLE_PRICE_WHERE`). **국가별 할인 우선, 없으면 글로벌 `Product.discount`(legacy 취소선) 폴백**(스택 안 함). **서버가 목적국별 최종가를 계산해 응답에 싣는다** — 공개 read `?country=`(미지정 US), 응답 `customerPriceUsd`/`listPriceUsd`/`customerDiscountPercent`/`freeShipping`. 1라인 단일 출처 `pricing/price-line.ts priceLine(row, cp, fxRate, currencyUsdRate, promotionPriceLocal)` — 표시(`attachCustomerPricing`)·주문·견적이 모두 거쳐 **표시가 == 청구가** 보장.

## 제품 태그 자유 텍스트 + 고정 키워드 폐지 (2026-07-30)

제품의 **주요 고민(`Product.concerns`)·추천 피부 타입(`Product.recommendedFor`)은 고정 enum 이 아닌 자유 텍스트 태그**다. 저장 정본은 **영문**(`EnglishTagList` — ASCII printable 만, concerns 8개 / recommendedFor 6개 × 40자)이고, 브랜드는 한글로 입력하면 `TagChipInput` 이 칩 추가 시점에 `POST /v1/brand/translate` 로 영문화하며 제출 직전 `resolveEnglishForSubmit` 이 놓친 한글을 일괄 번역한다(⚠️ 번역 API 는 요청당 20개 상한 → 20개씩 청크). 고객에게는 `ProductTranslation` MT 캐시(`concerns`/`recommendedFor` **`Json?`** 컬럼 — `null`=미번역 self-heal 마커 / `[]`=번역했고 원문 없음, `String[]` 은 null 을 못 담아 Json 을 쓴다)가 로케일별 번역을 실어 내려주고, klow_web PDP 는 `product.concerns`/`recommendedFor` 를 **클라 사전 매핑 없이 그대로** 렌더한다. 어드민 폼은 같은 태그 입력이지만 번역 없이 영문 직접 입력(`TagsInput verbatim asciiOnly`). 자동저장은 non-ASCII 태그가 하나라도 있으면 patch 를 보내지 않는다(`englishTagArraySpec` — 안 그러면 400 이 제품명·고시 저장까지 막는다). 같은 커밋에서 **고정 키워드 기반 기능 전부 제거**: `CONCERNS`/`SKIN_TYPE_LABELS` enum·`concern-tags.ts`·**discover 모듈 전체**(`/v1/discover*` → `GET /v1/products?sort=popular` 로 대체, 평점·리뷰수 순)·`/v1/shop/today`+어드민 샵설정·klow_web 온보딩 피부/고민 스텝(국가 선택 전용 모달로 축소)·SkinCard·`/my` 피부 프로필·`/shop` ConcernPicks·SkinTwinCreators·`/feed` 고민 탭·`/discover` 크리에이터 필터·어드민 리뷰 피부 필터. DB 컬럼 8개 drop(`User.skinType/concerns`, `Creator.skinType/concerns`, `Video.concerns/forSkinTypes`, `Review.userSkinType`, `ShopSettings.todaysPickConcern`) — ⚠️ **DROP COLUMN 이라 롤링 배포 비안전**(단일 레플리카 컷오버). 기존 데이터는 `npm run backfill:product-tags-english`(기본 dry-run, `-- --apply` 로 반영, **멱등**)이 `hydration`→`Hydration`·`건성`→`Dry skin` 으로 변환하며 `prisma.product.update` 로 `updatedAt` 을 올려 MT 캐시를 무효화한다. 매핑 동결 테이블은 `prisma/legacy-tag-labels.ts`(백필·시드 공용). 배포 순서·검증은 [`docs/archive/deploy-free-text-product-tags-runbook.md`](../archive/deploy-free-text-product-tags-runbook.md).

## 현장(박람회 부스) QR 판매 + 국가별 현장가 (2026-08)

브랜드가 부스에서 QR 을 띄우면 손님이 자기 폰으로 스캔해 즉석 결제한다(`?mode=onsite` → klow_web 간소 체크아웃, **배송 없음** — 부스 직접 전달). 가격 모델은 **스튜디오 제품 가격 설정과 동일한 2층 구조**다: **기준가는 USD 단일 값**(국가 무관), **국가별 핀은 현지통화 major 로 입력·저장**, **청구는 항상 USD 센트**. 다만 입력이 `원가+마진` 두 칸이 아니라 **`정산가(₩)` 한 칸**이고(즉석 판매라 값 하나로 끝냄), 국가 모달에 **할인·무료배송·배송원가 비교가 없다**(배송이 없으므로). 저장은 `Product.onsitePriceUsd`(청구 정본, USD 센트) + `Product.onsiteSettleKrw`(브랜드가 친 ₩ 원문 — **표시 전용**, USD 왕복 ceil/floor 잔차 ~13원이 입력칸에 되비치는 걸 막는다) + `Product.onsiteExcluded` + **`ProductOnsiteCountryPrice(productId, iso2, priceLocal)`**, 전부 `PUT /v1/brand/products/onsite` 한 번(디바운스 700ms)에 나간다. ⚠️ **`ProductCountryPrice` 에 컬럼을 붙이지 않고 테이블을 나눈 이유는 가격 모델이 달라서가 아니라 쓰기 격리다** — 양쪽 저장이 모두 replace-all(`deleteMany`→`createMany`)이라 한 테이블에 두면 스튜디오 저장이 현장 핀을, 현장 저장이 일반 핀·할인·무료배송을 조용히 전멸시킨다. 가격 산출 단일 출처는 **`pricing/price-line.ts onsitePriceLine(row, ocp, fxRate, currencyUsdRate)`** — 표시와 청구(`orders.createOnsite`)가 같은 함수를 거쳐 표시가==청구가를 보장한다. 현장/일반 분기는 **`PricingCtx.onsite`** 로 `attachCustomerPricing()` 안에서 끝나고(호출부가 DTO 를 사후에 안 덮어쓴다), 현장 원본 4종은 선언적 `StrippedPricingKeys` 로 공개 응답에서 벗겨진다 — 예전 ad-hoc `delete` 방식에선 새 컬럼 `onsiteSettleKrw` 가 곧바로 누락돼 샜다. 우선순위는 **목적국 핀 > `onsitePriceUsd` > `defaultListUsd(row)`**(신모델 `salePrice`+`basePriceFxRate` 파생 / legacy `basePriceUsd`). ⚠️ 마지막 폴백이 `basePriceUsd ?? 0` 이던 시절엔 `basePriceUsd` 가 null 인 신모델 제품이 현장에서 **$0 으로 팔렸다**(회귀 가드 `__tests__/onsite-pricing.spec.ts`). 손님 국가는 **배송지가 아니라 가격 기준국**이고(`POST /v1/orders/onsite` 의 `countryCode?`, 미지정 US, 파생은 `pricingIso2()` 단일 출처), klow_web 은 브랜드관 진입 시 고른 `useAppStore.country` 를 그대로 보낸다. **손님이 직접 바꿀 수 있다** (2026-08) — 브랜드관 좌상단 지구본(`BrandStorefront` 의 `AppChrome`, 현장/일반 공통 헤더라 분기 없음)이 기존 국가 선택 모달(`OnboardingModal`)을 열고, `country` 가 상품 쿼리 queryKey 에 있어 현장가가 즉시 재조회된다. ⚠️ **카트 라인은 담을 때 `customerPriceUsd` 를 스냅샷**하므로 국가만 바뀌면 표시가 != 청구가가 된다 → `OnboardingModal.select()` 가 **가격 기준국이 실제로 바뀔 때만**(`persistedCountry ?? `concerns`(주요 고민) / `recommendedFor`(추천 피부 타입) / `keyIngredients`(핵심 성분) 세 배열은 **저장 순서 그대로가 고객 화면 순서**인데, 브랜드가 그 순서를 정할 수단이 없어 입력 순으로만 쌓였다(바꾸려면 전부 지우고 재입력). klow_brand 스튜디오 제품 편집 폼에서 **드래그로 재정렬**할 수 있게 했다 — 칩은 `TagChipInput`(칩 전체가 핸들, sortable id = 칩 값 문자열 — `add()` 의 대소문자 무시 dedupe 가 유일성을 보장한다), 성분 행은 신규 `KeyIngredientRows.tsx`(⚠️ **그립에서만** 드래그가 시작된다 — 행 전체를 핸들로 만들면 입력칸 텍스트 선택이 죽는다). ⚠️ **klow_server·klow_web 은 무변경**이다 — 순서가 이미 끝에서 끝까지 보존된다(zod·저장·`localize()` 어디에도 정렬·dedupe 가 없고, klow_web PDP `ProductAccordionCard` 는 서버 배열을 변형 없이 렌더하며 성분 `01/02/03` 번호도 배열 위치에서 파생된다). 스키마·마이그레이션·백필·배포 순서 제약 전부 없다(klow_brand 단독 배포). ⚠️ **앞으로도 이 세 배열을 서버·클라 어디서도 정렬하거나 중복제거하지 말 것** — 넣는 순간 브랜드가 정한 순서가 조용히 뭉개진다. ⚠️ 재정렬이 안전한 이유는 `recommendedFor` 프리셋 overlay 가 원문↔캐시를 **인덱스로 짝짓는데도** 재정렬이 `prisma.product.update` 를 타 `@updatedAt` 이 올라가 캐시가 스테일로 재번역되기 때문이다 — **raw SQL·`updateMany` 로 순서만 바꾸면 로케일 라벨이 한 칸씩 밀린다.** ⚠️ 성분 행 id 는 `useRef` 로 들고 추가/삭제/재정렬 때 값 배열과 같이 움직인다(`{name, effect}` 는 타이핑마다 새 객체이고 둘 다 빈 값일 수 있어 값 기반 id 가 불가능, 인덱스 id 는 드롭 애니메이션이 죽는다). ⚠️ `KeyIngredientRows.onChange` 는 **함수형 setState** 를 받는다 — blur 번역이 비동기라 `apply` 시점에 최신 배열을 읽어야 다른 칸에 타이핑한 값을 덮어쓰지 않는다. ⚠️ 그립·프리셋 버튼은 `type="button"` + `preventDefault` 가 둘 다 필요하다(`Field` 가 자식을 `<label>` 로 감싼다 — 없으면 제품 폼이 통째로 제출되거나 첫 입력칸이 포커스된다). 자동저장은 두 필드 모두 **순서 민감 `JSON.stringify` 비교**라 순서만 바꿔도 PATCH 가 나간다(`useProductAutoSave.ts`). 자세히는 [`docs/server/modules/products.md`](../server/modules/products.md).

## 브랜드 수동 번역 — 목업 인라인 편집 (2026-08-25)

## 제품 가리기(`hidden`)는 온라인 전용 — 현장은 안 가려진다 (2026-09-10)

브랜드 요청. `hidden`("이 제품 가리기")은 **온라인 브랜드관에서 내린다**는 뜻이고, 부스에서 손님에게 직접 파는 축은 **별개 컬럼 `onsiteExcluded`** 가 담당한다 — 두 축은 직교이며 온라인에서 내린 제품도 부스에서는 계속 팔린다. 게이트를 둘로 쪼갰다: `PURCHASABLE_PRODUCT_WHERE`(= `PUBLIC_PRODUCT_WHERE`, `hidden:false` 포함) / **`ONSITE_PRODUCT_WHERE`**(같은 게이트에서 `hidden` 만 뺀 것), JS 짝은 `isPurchasable(p, { onsite })`. ⚠️⚠️ **현장 경로 셋이 전부 같은 게이트를 써야 한다** — 브랜드관 목록(`findAll` 의 `onsiteMode`) · PDP(`findOne` 의 `opts.onsite`) · **주문 생성(`orders.createOnsite`)**. 목록만 바꾸면 손님이 부스 화면에서 담을 수는 있는데 결제만 400 이 되어 **카드를 꺼낸 뒤에 막힌다**(타입도 응답 shape 도 그대로라 조용하다). ⚠️ **온라인 축에는 절대 쓰지 말 것** — `/shop`·검색·서버 카트는 `PUBLIC_PRODUCT_WHERE` 그대로다(쓰는 순간 내린 제품이 온라인에 되살아난다). 로그인 손님이 부스에서 담으면 `cart.service.upsert` 가 400 이지만 klow_web 이 `.catch(devWarn)` 로 삼키고 현장 결제는 로컬 카트를 직접 보내 구매는 정상이며, 가려진 제품이 그 손님 **온라인 카트에 안 남는 게 오히려 맞다**. ⚠️ **`hidden` 만 면제된다** — 미승인·미완성(대표사진/판매가)·브랜드 미승인·구독 만료는 부스에서도 그대로 막힌다. ⚠️⚠️ **파급: `hidden` 의 뜻이 좁아진다.** 부스 진입 URL `klow.kr/{slug}?mode=onsite` 는 **토큰 없는 공개 주소**라, 누구든 브랜드관 주소에 `?mode=onsite` 를 붙이면 가려진 제품을 볼 수 있다 — 이제 `hidden` 은 "고객에게 안 보임"이 아니라 **"기본 온라인 브랜드관에 안 보임"** 이다(완전히 감추려면 현장 탭에서 `onsiteExcluded` 도 함께 꺼야 한다). ⚠️ **klow_brand 현장 설정 보드가 `filter(!p.hidden)` 로 가려진 제품을 빼고 있었다** — 그대로 두면 브랜드가 온라인에서 내린 제품의 **현장가를 정할 수 없어** 기준가 파생값으로 팔리거나 현장 제외도 못 한다(서버 `saveOnsiteConfig` 는 원래부터 `hidden` 을 안 봐 저장은 이미 열려 있었다). 스튜디오 가리기 안내엔 "현장 QR 판매에는 영향이 없습니다" 를 명시하고, klow_admin 배지는 `브랜드 가림 · 비노출` → **`브랜드 가림 · 온라인 비노출`**(그냥 '비노출' 이면 운영자가 "아예 못 파는 제품"으로 읽는다). **마이그레이션·백필 없음 · 라우트·cron 불변 · klow_web 무변경.** 회귀 잠금은 `products/__tests__/onsite-hidden-gate.spec.ts`(9) — 특히 **두 게이트의 차이가 `hidden` 하나뿐임을 구조로 단언**한다(한쪽에만 조건이 늘면 "부스에서만 안 팔린다"가 되는데 그건 화면 어디에도 신호가 없다). 배포 순서는 **klow_server → klow_brand → klow_admin**. 자세히는 [`docs/server/modules/products.md`](../server/modules/products.md).
