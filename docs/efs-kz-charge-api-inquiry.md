# [문의] getTrackStatus API — 카자흐스탄(KZ) 배송비(예상 배송 비용) 미회신 건

> EFS 담당자님께 보낼 문의 초안입니다. (API 문서: `EFS_ShippingOrder_API_v3.5`)

---

**제목:** getTrackStatus 응답의 배송비(10번 필드)가 카자흐스탄行 송장에만 0으로 회신되는 건 문의

안녕하세요, KLOW(웰킷) 개발팀입니다.

`getTrackStatus`(req_function) API로 송장별 배송비(회신 규격 **10번 필드 "배송비 / 예상 배송 비용(KRW)"**)를 조회하고 있습니다. 그런데 **카자흐스탄(KZ)行 송장은 배송비가 항상 `0`으로 회신**됩니다. 반면 미국(US)·캐나다(CA)·러시아(RU) 등 다른 목적국은 정상적으로 값이 옵니다.

EFS 정산 어드민 페이지에는 해당 KZ 송장들의 배송비가 정상적으로 표기되어 있어, API 회신값과 차이가 있어 문의드립니다.

## 1. 재현 방법

- 요청: `req_function=getTrackStatus`, `send_data=<송장번호>` (운영 `https://www.efs.asia:300/api/in/`)
- 아래 KZ 송장들은 **실측무게·서비스타입은 정상 회신되나 배송비(10번 필드)만 `0`**, 국가명(11번)도 빈칸으로 옵니다.

### KZ 송장 — 배송비 0 회신 (원문 그대로)

```
EFS1005148399 | ... |EG049399994KR|33|Delivered|2026.07.02 14:09|0.55,0.55,21,13,9,0.41|EMS|0|
EFS1005148372 | ... |EG049399985KR|33|Delivered|2026.07.03 11:53|0.63,0.63,21,13,9,0.41|EMS|0|
                                                    실측무게 ↑ 정상        배송비 ↑ = 0   국가 ↑ 빈칸
```

### 비교 — 다른 목적국은 배송비 정상 회신

```
EFS1005147348 (US) | ... |11|Ready for Onboard|2026.07.01 23:00| ... |PREMIUM|38280|Korea
EFS1005124155 (CA) | ... |33|Delivered|2026.06.22 11:19| ... |EMS|41500|Canada
EFS1005128534 (RU) | ... |72|Customs cleared| ... |EMS|35500|Russia
```

## 2. 목적국별 회신 현황 (2026년 6월 픽업분, 총 96건 기준)

| 목적국 | 송장 수 | 배송비 회신 있음 | 비고 |
|--------|--------:|----------------:|------|
| **KZ (카자흐스탄)** | **86** | **0건** | 전부 배송비 0 |
| US | 4 | 4건 | 정상 |
| RU | 2 | 2건 | 정상 |
| CA | 1 | 1건 | 정상 |
| AT / PT / EG | 각 1 | 0건 | 배송비 0 |

→ 물량의 대부분(86/96)이 KZ이며, KZ 건은 전부 배송비가 0으로 회신됩니다.

## 3. 문의 사항

1. **`getTrackStatus`의 배송비(10번 필드)가 KZ行 송장에 대해 0으로 회신되는 사유**가 무엇인가요? (KZ lane의 요율 미산정 / 예상값 미제공 / 후정산 대상이라 실시간 미노출 등)
2. **KZ行 송장의 배송비도 `getTrackStatus`로 정상 회신받을 수 있는 방법**이 있나요? (요청 파라미터·계정 설정 등)
3. 어드민 페이지에 표기되는 **확정 배송비(청구액)를 API로 조회할 수 있는 별도 엔드포인트(정산/청구 조회 등)** 가 있나요? 있다면 `req_function` 이름과 요청/회신 규격을 알려주시면 감사하겠습니다.

번거로우시겠지만 확인 부탁드립니다. 감사합니다.

## (내부 메모 — 발송 전 참고)

- 위 배송비 값은 문서상 **"예상 배송 비용"** 이라 최종 정산표 금액과 다를 수 있음. 실제 브랜드 청구는 우리 DB의 `SeedingLink.feeKrw` 기준이므로 이 API 값이 0이어도 청구 자체엔 영향 없음 — 어디까지나 대조/참고용.
- 별개로 확인된 사항(문의 대상 아님): `getTrackStatus` 배치 조회 구분자는 문서의 `CHR(10).CHR(13)`(LF+CR)이 아니라 **CRLF(`\r\n`)** 여야 동작함. 이 부분도 함께 지적할지 여부는 선택.
- 송장번호(HAWB)·수취인 정보가 포함되므로 외부 발송 시 민감정보 노출 주의(위 예시는 송장번호만).
