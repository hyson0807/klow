# buyer-sample-order — 바이어 샘플 주문 · 결제 · 합포장 송장

klow.kr 바이어 공간의 **샘플박스 → 체크아웃 → 결제** 목업(localStorage `kb.*` · 가짜 결제창)을 실제 흐름으로 바꾼다.
화면은 buyer-platform 23행이 디자인 그대로 이미 만들어 두었다(정본 [`../buyer-platform/mock-parity.md`](../buyer-platform/mock-parity.md)).

```
바이어(로그인) 샘플박스 → 엑심베이 결제(USD)
  → 브랜드: klow_brand '샘플 요청' 페이지 + 이메일 → KLOW 사무실로 발송 → '발송함'
  → 어드민: 바이어 주문 · 브랜드별 '입고 확인' · (못 보낸 품목은 부분환불)
  → 전 브랜드 입고 → 어드민 '송장 발급' = 여러 브랜드 1박스 · EFS 송장 1장(발송인 KLOW) → 라벨 → 트래킹
```

## BM — 왜 브랜드 정산이 없나

KLOW 가 브랜드 제품을 **도매가로 미리 사입**해 두고 바이어에게 **샘플가**로 판다. 결제금은 **전액 KLOW** 이고,
마진(샘플가 − 도매가)은 배송비로 쓴다. 손해가 나도 **바이어 정보 확보를 위한 투자**로 본다. 수익은 그 바이어가
대량 구매할 때 KLOW 가 **1차 벤더**로서 남긴다. → 브랜드 쪽에 바이어 신원을 보여주지 않는다(D8).

## 결정 (2026-10-14 사용자)

| # | 결정 |
|---|---|
| D1 | 결제 자격 = **로그인한 바이어 전부**(검수 대기 포함 — `verified` 불요). 구간가가 로그인만으로 열리는 정책과 같다 |
| D2 | **브랜드 정산 없음** — 결제금 전액 KLOW. 바이어 주문은 정산 화면·`SETTLEABLE_ORDER_WHERE` 에 들어가면 안 된다 |
| D3 | 배송비 = **목적국 500g 티어 요율 1회**(소비자 일반 주문과 같은 값·같은 원→USD 환산). **SKU 5개 이상이면 무료**(샘플 = 제품당 1개라 SKU 수 = 품목 수) |
| D4 | 입고 흐름 = 브랜드 **'발송함'**(국내 택배사·송장번호는 선택 입력) + 어드민 **'입고 확인'**(브랜드 단위). 합포장 송장은 취소 안 된 **전 브랜드가 입고된 뒤에만** 발급 |
| D5 | 브랜드가 못 보내면(품절 등) = 어드민이 **해당 품목만 부분환불**(엑심베이 부분취소) 후 나머지만 발송 |
| D6 | 브랜드 알림 = **이메일** + 어드민 상세에서 브랜드별 미반응(경과시간) 확인 → 운영팀이 직접 연락. **알림톡 없음** |
| D7 | KLOW 발송인(이름·주소·우편번호·전화) = **어드민 설정 화면에서 입력**(`ShopSettings`). 브랜드 페이지의 "여기로 보내 주세요" 주소도 같은 값 |
| D8 | 브랜드에게는 **바이어 신원(회사·이메일·주소)을 내려주지 않는다** — 국가·제품·수량만. 직거래 우회 방지(계획 세션 판단 — 사용자가 뒤집을 수 있다) |

## 스코프 밖

- 서버 장바구니 — 샘플박스는 localStorage 그대로, **서버가 주문 생성 시 가격·노출·배송비를 전부 재계산**한다
- 브랜드 정산(D2) · 알림톡(D6) · 사입 재고 관리(사입은 시스템 밖)
- 바이어 리뷰·Concierge·채팅 — buyer-platform 25행
